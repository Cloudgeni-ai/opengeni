Use this to develop against OpenGeni or try it before self-hosting. For production, see [Self-host](/guides/self-host).

## Prerequisites

- macOS or Linux (WSL2 on Windows).
- [Bun](https://bun.com/docs/installation) at the version in `.bun-version`.
- Git and curl.
- Docker with a running daemon, or the native services described in [Local development](https://github.com/Cloudgeni-ai/opengeni/blob/main/docs/local-development.md).

Run `bun run dev:check` to diagnose missing prerequisites.

## Start the stack

```bash
git clone https://github.com/Cloudgeni-ai/opengeni.git
cd opengeni
bun run dev
```

This installs dependencies, starts Postgres, NATS, Temporal and object storage, runs migrations, and starts the API, workers and web app. Wait for `OpenGeni dev stack ready`; the first start can take several minutes.

| Service    | URL                           |
| ---------- | ----------------------------- |
| Web app    | http://127.0.0.1:3000         |
| API        | http://127.0.0.1:8000         |
| API health | http://127.0.0.1:8000/healthz |

If a port is busy, the launcher picks a free one and prints the URLs it used.

The local stack has no login: it runs as a single `dev` user with broad permissions. By default the agent runs commands directly on your machine, so everything listens only on `127.0.0.1`. To run the agent in a container instead, set `OPENGENI_SANDBOX_BACKEND=docker`.

Connect a model in **Organization settings → Models**, or set a key in `.env`.

## Configure

`.env` holds all configuration. Common settings:

| Variable                                | Purpose                                                                               |
| --------------------------------------- | ------------------------------------------------------------------------------------- |
| `OPENGENI_OPENAI_API_KEY`               | OpenAI credentials for the default provider                                           |
| `OPENGENI_OPENAI_MODEL`                 | Default model for new sessions                                                        |
| `OPENGENI_MODEL_PROVIDERS_JSON`         | Additional OpenAI-compatible providers and their models                               |
| `OPENGENI_SANDBOX_BACKEND`              | Where sessions run: `local` (default), `docker`, `modal`, `none`, or a cloud provider |
| `OPENGENI_SANDBOX_PREPARATION_PROFILES` | Profiles such as `azure` or `github` that sign in CLIs inside the sandbox             |
| `OPENGENI_SANDBOX_SELFHOSTED_ENABLED`   | Set to `true` to enable Connected Machines                                            |
| `OPENGENI_LOCAL_ALLOWED_ORIGINS`        | Extra browser origins allowed to call the local API, such as your own front end       |

Model credentials stay out of the agent sandbox unless you allow them. See the [model providers guide](https://github.com/Cloudgeni-ai/opengeni/blob/main/docs/model-providers.md).

## Troubleshooting

- **Bun version mismatch:** install the pinned version with `curl -fsSL https://bun.com/install | bash -s "bun-v$(cat .bun-version)"`.
- **Database errors after switching branches:** the database must match the checkout. Run `bun run dev:clean -- --yes` to start fresh (this deletes local data).

## Stop

Press Ctrl-C to stop the launcher, then:

```bash
bun run dev:down
```

`bun run dev:clean -- --yes` also deletes this checkout's local data.

## Run tests

Typechecks and unit tests need no running services:

```bash
bun run typecheck
bun run test:unit
```
