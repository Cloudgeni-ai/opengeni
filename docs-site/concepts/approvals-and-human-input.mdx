A session can pause mid-turn and wait for a person in two ways. The wait survives worker restarts, and the answer resumes the same turn.

## Tool approvals

A tool can require approval before it runs. When the agent proposes such a call, the session enters `requires_action` and the timeline shows the pending call. A person approves or rejects it; a rejection goes back to the agent so it can adapt. Only humans can approve tool calls.

## Structured human input

Agents can ask questions with the built-in `request_human_input` tool. A request holds up to 20 free-text, single-select, or multi-select questions, and can allow Skip and set a deadline.

The agent receives one of these outcomes:

| Outcome     | When                                          |
| ----------- | --------------------------------------------- |
| `answered`  | The person submitted answers                  |
| `skipped`   | The person skipped and the request allowed it |
| `expired`   | The deadline passed                           |
| `cancelled` | The turn was replaced or stopped              |

Workspace admins can turn the tool off with the `agentHumanInputEnabled` setting.

## Sending a message while the session waits

An ordinary message sent during either wait cancels it and is delivered as a Steer, so "actually, do this instead" is one action.

## Answering from your product

`SessionConversation` from `@opengeni/react` renders both kinds of wait. To answer from your own UI or backend, see [Approvals & questions](/integrate/approvals-and-questions).
