A **session** is one conversation and workstream: its history, settings, visibility, and compute. Sessions belong to a workspace.

## Sessions, turns, and attempts

| Identity | Meaning                                                                        |
| -------- | ------------------------------------------------------------------------------ |
| Session  | The conversation and its context. Lives until deleted.                         |
| Turn     | One unit of input: a prompt, a machine input, a goal continuation, a schedule. |
| Attempt  | One worker execution of a turn. A crashed worker is replaced by a new attempt. |

A new attempt never means a new prompt, so Opengeni can recover a turn after a worker dies without repeating it.

## The event log

Every session event is stored in Postgres with a sequence number. Clients read it two ways:

- **Replay**: fetch events after a sequence.
- **Stream**: subscribe over Server-Sent Events. The SDK resumes by sequence after a drop and fills gaps from replay.

A reload, a second client, or an audit all see the same history.

## Sending input

- **Send** appends a prompt. If a turn is running, the message queues behind it. Queued messages stay editable and reorderable until they start.
- **Steer** moves your message to the front and interrupts the running turn.
- **Pause** and **Resume** hold and release the session.
- **Cancel** stops the session and its children for good.

If the session is waiting on you for an approval or a question, Send replaces that wait with your new prompt.

## Attached context

A session can carry repositories, uploaded files, workspace documents, selected tools, and Skills. If you omit the tool list, the session uses the workspace default.

## Artifacts

The workspace **Artifacts** page collects Sites, documents, spreadsheets, presentations, images, and published files, with filters and search. A session's Artifacts panel shows the outputs of that conversation.

Spreadsheet artifacts are editable in place: enter values or formulas, paste a range, and drag row or column header boundaries to resize them. Changes use the same live workbook in the session panel and full artifact view. Saving runs in the background; read-only access disables editing and resizing.

The agent publishes the files it means to deliver; files it only writes to disk stay in the sandbox. Images, video, audio, and PDFs preview in chat. Other formats download.

## Child sessions

An agent can spawn child sessions for parallel or delegated work. Children are ordinary sessions. When one finishes, its final answer is delivered to the parent's next turn.

## Visibility

Sessions in a shared workspace are visible to its members. An organization owner can let members create **Only me** sessions. Personal workspaces belong to one person.

## Connected accounts

Open **Connectors** in the composer to choose which connected accounts the agent may use. Each account is marked **Only me** or **This workspace**. Add accounts from the connector's **Capabilities** page.

Personal accounts belong to whoever sends the message, even in a shared session; other participants can't use them by replying. Scheduled tasks use their owner's accounts. If you attach several accounts, say which one to use for actions that send or change data.

## Agent access in product integrations

`agentAccess` controls which other sessions an agent can reach in its workspace:

| Scope       | Agent reach                                                    |
| ----------- | -------------------------------------------------------------- |
| `session`   | Its own session tree, including children                       |
| `user`      | Other trees with the same product user label, if they allow it |
| `workspace` | Other trees in the workspace, if they allow it                 |

The stricter side wins, and children can only narrow their parent's scope. This does not hide sessions from workspace members; your backend still authorizes each user's requests.

The chat API defaults to private chats with `agentAccess: "session"` (`chats: "shared"` uses `"workspace"`). Raw session creation defaults to `"workspace"`. Access and [Knowledge](/concepts/memory-and-knowledge) scope are set when a conversation is created. See [Users, tenants & privacy](/integrate/users-and-tenants#choose-who-shares-chats).

## Browsing and archiving

The sidebar groups sessions by project or creator. **Active** hides archived sessions; **All** shows them in a collapsed **Archived** folder. Archiving offers **Undo** for a few seconds, and you can restore later from **Archived**.

## Model settings

Follow-ups without an explicit choice reuse the model, reasoning effort, and speed of the latest turn. Child sessions inherit the parent's model and reasoning effort but start at **Standard** speed.

**Codex subscription source** in workspace model settings picks between workspace and organization subscriptions. **Automatic** prefers the workspace's own. A change applies to new work only.

## Voice input

**Voice input** in workspace settings sets the default transcription provider. **Automatic transcription fallback** tries another configured provider when the preferred one fails; that provider's billing applies. Your recording is kept while transcription retries.

## Fast code search

When your deployment offers it, **Fast code search** in workspace settings gives agents a `code_search` tool that returns the most relevant source passages for a question about a codebase, in one call. It applies to sessions created after you turn it on.
