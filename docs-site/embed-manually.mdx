You add one proxy route to your backend and render `<OpenGeniChat />` in your frontend. The browser talks to your backend; your backend holds the API key.

```bash
bun add @opengeni/sdk @opengeni/react
```

Keep all `@opengeni` packages on the same version.

<Steps>
  <Step title="Get an API key">
    Sign up at [app.opengeni.ai](https://app.opengeni.ai). In **Organization settings → Developer**, create a **full-access** API key scoped to **all shared workspaces**. Copy the **Organization ID** from **Organization settings → General**.

    ```bash
    OPENGENI_API_BASE_URL=https://app.opengeni.ai   # or your self-hosted API
    OPENGENI_ORGANIZATION_ID=...
    OPENGENI_API_KEY=ogk_...                        # server only
    ```

    See [Authentication](/reference/authentication) for key scopes.

  </Step>
  <Step title="Onboard each user">
    Each tenant maps to an Opengeni workspace, and each user must be a member of it. Run this once when your product admits a user:

    ```ts
    // lib/opengeni.ts
    import { OpenGeniClient } from "@opengeni/sdk";

    export const og = new OpenGeniClient({
      baseUrl: process.env.OPENGENI_API_BASE_URL!,
      apiKey: process.env.OPENGENI_API_KEY!,
    });
    export const source = "acme-product"; // namespace for your user ids

    export async function onboard(tenant: Tenant, user: User, operationId: string) {
      const { workspace } = await og.ensureWorkspace({
        accountId: process.env.OPENGENI_ORGANIZATION_ID!,
        externalSource: source,
        externalId: tenant.id,
        name: tenant.name,
      });
      await og.addExternalWorkspaceMember(workspace.id, {
        identity: { externalId: user.id, source },
        permissions: [
          "workspace:read",
          "sessions:create",
          "sessions:read",
          "sessions:control",
          "files:upload",
          "files:read",
          // add "mcp_servers:attach" to give the agent your own tools
        ],
        operationId, // a UUID you store; reuse it only to retry this call
      });
      return workspace.id; // store the tenant -> workspace mapping
    }
    ```

    If each user should get their own workspace instead, skip this step: pass the `OpenGeni` facade from `@opengeni/sdk/chat` to the proxy with `chats: "isolated"` and return `{ tenant, user }` from `resolve`. It creates the workspace and membership on first use. See [Users, tenants & privacy](/integrate/users-and-tenants).

  </Step>
  <Step title="Mount the proxy">
    With the Next.js App Router, in `app/api/opengeni/[...path]/route.ts`:

    ```ts
    import { createSessionProxyRoute } from "@opengeni/sdk/next";
    import { authenticate, verifyCsrf } from "@/lib/auth"; // your product's own checks
    import { og, source } from "@/lib/opengeni";

    export const dynamic = "force-dynamic";
    export const { GET, POST, PUT, PATCH, DELETE } = createSessionProxyRoute(og, {
      chats: "private", // "shared" lets the team see each other's chats
      resolve: async (request) => {
        const me = await authenticate(request);
        if (!me) return new Response("Unauthorized", { status: 401 });
        return { workspaceId: me.workspaceId, user: me.userId, source };
      },
      authorizeMutation: (request) => verifyCsrf(request),
      // The browser sends only the first message; you choose the rest.
      createSession: ({ initialMessage, idempotencyKey }) => ({
        initialMessage,
        idempotencyKey,
        agent: {
          identity: "You are Acme's assistant. Friendly and brief.",
          capabilities: "none",
        },
        tools: [],
        sandboxBackend: "none", // a chat-and-tools agent needs no sandbox
      }),
      // Your own tools, called as the signed-in user:
      // toolServer: { url: "https://app.example.com/api/mcp", approvals: { ask: ["rename_post"] } },
    });
    ```

    Private chats must be enabled for your organization; if they aren't, the proxy throws `OpenGeniSetupError` saying who can turn them on. For agent options, see [Configure the agent](/integrate/configure-the-agent).

    Express and Hono have adapters in `@opengeni/sdk/express` and `@opengeni/sdk/hono` (see the [SDK reference](/reference/sdk#framework-adapters)). For other backends, see [Proxy from any backend](/integrate/proxy-from-any-backend).

  </Step>
  <Step title="Render the conversation">
    ```tsx
    import { OpenGeniClient } from "@opengeni/sdk";
    import { OpenGeniChat, OpenGeniProvider } from "@opengeni/react/session-ui";
    import "@opengeni/react/compiled.css";

    const client = new OpenGeniClient({ baseUrl: "/api/opengeni" });

    export function Assistant({ workspaceId }: { workspaceId: string }) {
      return (
        <OpenGeniProvider client={client} workspaceId={workspaceId}>
          <OpenGeniChat />
        </OpenGeniProvider>
      );
    }
    ```

    `OpenGeniChat` shows the user's chats and the conversation. For an assistant tied to one record, create the session on your server with `og.asUser(userId, { source }).createSession(...)` and render `<SessionConversation sessionId={id} />`. The stylesheet is scoped and needs no Tailwind. See [Conversation UI & theming](/integrate/conversation-ui).

  </Step>
</Steps>
