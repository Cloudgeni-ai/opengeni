Opengeni's public API is a workspace-scoped HTTP API. Most integrations should use [`@opengeni/sdk`](/reference/sdk), which wraps these routes with types, retries, and stream recovery. Every request authenticates first (see [Authentication](/reference/authentication)).

## Billing

API and embedded-product usage spends credits, not plan credit. Connected AI subscriptions are available only in the Opengeni apps on Pro ($20/month), Max, or Enterprise; API requests that explicitly select one return `403` with `subscription_api_unavailable`. A self-hosted deployment can allow them for API requests with `OPENGENI_API_CONNECTED_SUBSCRIPTIONS_ENABLED=true`; see [Self-host](/guides/self-host#connected-subscriptions-over-the-api). See [Going to production](/integrate/production) for billing and model selection.

## Discovery

| Route                   | Returns                                                         |
| ----------------------- | --------------------------------------------------------------- |
| `GET /healthz`          | Liveness and the server version                                 |
| `GET /v1/config/client` | Deployment features and client configuration, including version |
| `GET /v1/access/me`     | The caller's organization and workspace grants                  |

## Main route families

| Family                | Routes                                                                                                                                |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Organizations         | `/v1/organizations/:organizationId/...`: API keys, members, workspaces, organization-wide session lists                               |
| External workspaces   | `PUT /v1/workspaces/external` (idempotent `ensureWorkspace`)                                                                          |
| Sessions              | `POST /v1/workspaces/:workspaceId/sessions`, `GET .../sessions/:sessionId`                                                            |
| Events                | `GET .../sessions/:sessionId/events` (replay), `POST .../events` (messages, approvals, answers)                                       |
| Control               | `POST .../sessions/:sessionId/steer`, `POST .../sessions/:sessionId/control` (pause, resume, cancel)                                  |
| Live stream           | `GET .../sessions/:sessionId/events/stream` (Server-Sent Events, resumable by sequence)                                               |
| Goals                 | `GET`, `PATCH`, and `DELETE` on `.../sessions/:sessionId/goal`                                                                        |
| Files                 | Upload begin and complete, download URLs                                                                                              |
| Scheduled tasks       | `/v1/workspaces/:workspaceId/scheduled-tasks/...`, including their event triggers                                                     |
| Event sources         | `/v1/workspaces/:workspaceId/event-sources/...`, and the public webhook URL each source returns                                       |
| Integrations          | `/v1/workspaces/:workspaceId/integrations/...` (preview, install, uninstall)                                                          |
| Connected Machines    | `/v1/workspaces/:workspaceId/enrollments/...`                                                                                         |
| Webhooks, credentials | `/v1/workspaces/:workspaceId/webhooks/...` and `.../credential-provider`, plus the same under `/v1/organizations/:organizationId/...` |
| Usage allowances      | `.../allowance`, `.../usage/me` on a workspace (or `/v1/workspaces/external/:source/:externalId`)                                     |

## Session model defaults

`PUT /v1/workspaces/:workspaceId/sessions/:sessionId/model-settings` updates `model`, `reasoningEffort`, and `latencyMode` without sending a message. It needs `sessions:control` and access to the session; a workspace API key can call it. Supply a UUID `idempotencyKey`; an exact retry returns the original result. Pass any of the current settings in `expected` to compare before writing. A mismatch returns `409` with all three current settings in `error.details.current`; an unsupported or disallowed setting returns `400` without substituting a value.

The defaults apply to newly admitted turns, including scheduled turns that inherit the session defaults. Running and already queued turns keep their settings; a turn waiting on subscription capacity can continue on the new model. The response includes `releasedCapacityWaitTurnId` when that happens.

### Organization Skills from a product backend

Use a server-side organization API key with explicit `account:admin` and
`workspace:read` and an all-shared-workspaces key policy. Do not use `asUser()`
or send the key to a browser. Name a shared workspace of that organization in
the path; the saved Skill belongs to the organization, not to that workspace.

`POST /v1/workspaces/:workspaceId/organization-skills/save` (`saveOrganizationSkill`)
accepts `operationId`, `skillId`, `expectedRevisionId`, `expectedScopeVersion`,
`stableKey`, `files` (`{ path, content }[]`), optional `deletions` (file paths),
`reason`, and optional `initialReach`. For a new Skill, use a new Skill UUID,
`expectedRevisionId: null` and `expectedScopeVersion: 1`. It is active on
success; the write is attributed to the key, not to a person or agent.

`initialReach` is `{ allowedWorkspaceIds, allowPersonalWorkspaces }`. A list
allows those shared workspaces only (at most 500); `null` allows every shared
workspace, including new ones. `allowPersonalWorkspaces` is a separate boolean.
Omitting `initialReach` on creation retains the default of every workspace,
including Personal. If supplied, reach and activation commit together.

For later reach changes use `PUT /v1/workspaces/:workspaceId/organization-skills/:skillId/reach`
(`updateOrganizationSkillReach`) with the same reach object. For permanent removal
use `POST /v1/workspaces/:workspaceId/organization-skills/:skillId/remove`
(`removeOrganizationSkill`) with `operationId`, `expectedRevisionId`,
`expectedScopeVersion`, and `reason`. Save and remove return a `SkillWriteReceipt`;
retry uncertainty with the same operation ID and input.

## Streaming

The event stream is Server-Sent Events. Every event has a sequence number, so a client can reconnect with the last sequence it saw and fill any gap from the replay route. Disable proxy buffering and set read timeouts of at least an hour.

## Compatibility

The API only grows, and server updates don't break existing integrations: servers accept every request a published SDK sends, and clients ignore unknown fields and event types. Rare exceptions (an emergency security fix or an explicit product-owner decision) are announced with migration notes. See [Going to production](/integrate/production#keep-sdk-and-server-compatible).

The full route list is in the repository's [HTTP API overview](https://github.com/Cloudgeni-ai/opengeni/blob/main/docs/http-api.md).
