Configure the credential provider and webhooks per workspace or once for the organization; see [Webhooks and credentials](/guides/webhooks-and-credentials). Each signing secret is returned once, at creation.

## One signature scheme

Every request Opengeni sends to your endpoints is signed:

```text
OpenGeni-Signature: t=<unix seconds>,v1=<hex HMAC-SHA256(secret, "<t>.<raw body>")>
```

Verify the raw body before parsing it:

```ts
import { verifyWebhookEvent, verifyCredentialProviderRequest } from "@opengeni/sdk";

const { event } = await verifyWebhookEvent({ body: rawBody, headers, secret });
const request = await verifyCredentialProviderRequest({ body: rawBody, headers, secret });
```

## Credential provider

An HTTPS endpoint that supplies short-lived credentials for sandbox work: environment variables, files, Git credentials, and MCP credentials. Opengeni calls it before a turn's sandbox work and again before they expire.

```ts
const { secret } = await og.putWorkspaceCredentialProvider(workspaceId, {
  url: "https://api.acme.com/opengeni/credentials",
  timeoutMs: 10_000,
});
```

Each request names the workspace, session, turn, and the user who started the work, so you can scope credentials to them. Respond with `ok` plus the credentials and an optional `expiresAt`, `not_applicable`, or `auth_needed` with a message to show the user.

## Webhooks

Up to ten endpoints per workspace, each subscribed to any of:

| Event                                                                | Sent when                                                                                                        |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `turn.completed` / `turn.failed` / `turn.cancelled`                  | A turn settles                                                                                                   |
| `session.status.changed`                                             | The session status changes                                                                                       |
| `session.requiresAction`                                             | The agent waits for a tool approval                                                                              |
| `session.humanInput.requested`                                       | The agent asks the user a structured question                                                                    |
| `usage.threshold_reached` / `usage.exhausted` / `usage.period_reset` | A [usage allowance](/guides/usage-allowances) crosses a threshold, runs out, or resets (workspace webhooks only) |

```ts
const { webhook, secret } = await og.createWorkspaceWebhook(workspaceId, {
  url: "https://api.acme.com/opengeni/events",
  eventTypes: ["turn.completed", "turn.failed", "session.requiresAction"],
});
```

The body identifies the session, turn, and sequence; read details through the API. Delivery is at least once and unordered: deduplicate on the event `id` and order by `sequence`. Failed deliveries retry with backoff; inspect and replay them with `listWorkspaceWebhookDeliveries` and `redeliverWorkspaceWebhookDelivery`.

## Turn identity on MCP calls

Every MCP tool call includes `_meta.opengeni` with the workspace, session, turn, and initiating user. Use it for logging; authorize with the connection's own credential.
