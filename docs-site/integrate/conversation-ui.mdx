`OpenGeniChat` shows the user's chats and the open conversation. The chat list is a sidebar when there is room and a drawer when there is not, so it fits a side panel or a full page. Users can start, rename, and archive chats.

```tsx
<OpenGeniChat baseUrl="/api/opengeni" conversationProps={{ toolRegistry }} />
```

`baseUrl` is your proxy's mount. The component creates the browser client and uses the workspace your proxy resolved for the signed-in user.

The new-chat composer is the same as the follow-up one: attachments, your `conversationProps.composerProps`, and the model picker when offered. Files attached to the first message are added to the new chat.

Live voice is off unless you turn it on, because each call is paid from your Opengeni credits per minute and asks the browser for the microphone. Pass `realtimeVoice: true` to `createSessionProxyHandler`, or `conversationProps={{ realtimeVoice: true }}`. The composer then shows a voice button when your workspace has a voice model available (for example hosted GPT Live). Starting voice in a new chat creates an empty conversation and starts the call there; typed text and attachments remain an unsent draft, not an invented first message. The user talks, the voice model answers, hands work to the agent in the same chat, and the transcript appears in the timeline. `realtimeVoice: false` on the proxy refuses voice even when the component asks for it.

The indicator shown while the agent starts says "Thinking…". Use `conversationProps={{ genieLoading: { phrases: ["One moment…"] } }}` for your own copy, or `genieLoading.render` for your own visual.

For anonymous visitors on a public site, return `visitor: true` from the proxy's `resolve`. Visitors get no attach button (the proxy also refuses their uploads) unless you set `visitorUploads: true`.

If your app authenticates with a bearer token instead of cookies, pass it on every request and read it in the proxy's `resolve`:

```tsx
<OpenGeniChat
  baseUrl="/api/opengeni"
  headers={() => ({ Authorization: `Bearer ${getAccessToken()}` })}
/>
```

The function runs per request, so it can return a refreshed token. Pass `fetch` instead when the token must be awaited. A `client` you pass with `baseUrl` is used instead of the one the component would create.

The list shows the chats the user created. Set `sessionList: "visible"` on the proxy to list every chat they can read. Control the selection with `sessionId` and `onSessionChange` (for example from the URL).

For a single conversation, use `SessionConversation`. It includes streaming replies, tool activity, approvals, questions, attachments, the message queue, Steer, and Pause/Resume.

```tsx
import { SessionConversation } from "@opengeni/react/session-ui";
import "@opengeni/react/compiled.css";

<SessionConversation baseUrl="/api/opengeni" sessionId={sessionId} height="100%" />;
```

Import from `@opengeni/react/session-ui` for the smallest bundle; it has no optional peer dependencies. To share one client across several components or use the headless hooks, wrap them in `<OpenGeniProvider client={client} workspaceId={workspaceId}>` instead of passing `baseUrl`.

## Props

| Prop                                                   | Purpose                                                                                  |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `sessionId`                                            | Required. The session to show                                                            |
| `baseUrl`                                              | Your proxy's mount, such as `/api/opengeni`. Not needed inside an `OpenGeniProvider`     |
| `headers`, `fetch`                                     | With `baseUrl`: headers for every request (static or a function), or a custom fetch      |
| `attachments`                                          | File attachments in the composer. Defaults to `true`                                     |
| `modelPicker`                                          | Show the model picker. Hidden unless the proxy sets `modelSelection: true`               |
| `toolRegistry`                                         | Your own renderers for your tools                                                        |
| `renderMessageText`                                    | Custom rendering for message text, such as links into your product                       |
| `renderAllowanceExhausted`, `allowanceExhaustedLabels` | Replace the row or its words when a [usage allowance](/guides/usage-allowances) runs out |
| `height`                                               | Defaults to filling its container                                                        |
| `className`                                            | Class on the root element                                                                |
| `composerProps`                                        | Composer options, such as placeholder text                                               |

Remount the component when the signed-in user or tenant changes.

## Keep a conversation across layouts

The default component needs no controller setup. If a conversation moves between
a side panel and a full-page view, mount `useSessionConversation` in a stable
parent and pass it to `SessionConversationView`. These are the same state and
view used by `SessionConversation`, not a second chat implementation.

```tsx
import { useSessionConversation, SessionConversationView } from "@opengeni/react/session-ui";

function PersistentConversation({ sessionId, recordContext, expanded, refreshRecord }) {
  // Under your OpenGeniProvider; explicit client/workspaceId also work.
  const conversation = useSessionConversation(sessionId, {
    composerOptions: {
      sendExtras: () => ({ modelContext: recordContext }),
      onSent: () => refreshRecord(),
    },
  });

  return (
    <section className={expanded ? "conversation-page" : "conversation-panel"}>
      <SessionConversationView conversation={conversation} />
    </section>
  );
}
```

Keep the controller mounted to retain the event stream, annotations, draft,
model policy and uploads when a view is replaced. Keep the view mounted too
while using live voice: the stock voice control owns the browser microphone
and call lifetime. Change layout with CSS rather than moving it between React
parents. Remount both on a signed-in user or tenant change.

Use `composerOptions.sendExtras` for application context and `onSent` for
post-acceptance notifications, not a custom `send` wrapper. The stock composer
continues to validate annotation-only messages, upload readiness, queueing and
retry identity. The same `modelContext` is captured for durable voice messages.
Notification exceptions are reported as browser errors; they cannot make an
accepted send appear failed. Context is ordinary model-visible content, not an
authorization mechanism or a place for secrets.

`chromeProps`, `humanInputProps` and `approvalProps` customize stock status
panels and decision presentation without replacing their action handlers.
`realtimeVoiceProps` provides optional connected-account state and voice
autostart handoff; live voice remains opt-in as before.

## A new conversation in your own layout

`OpenGeniChat` still needs no creation controller setup. Its new-chat state and
view are also available separately:

```tsx
<NewConversation baseUrl="/api/opengeni" onCreated={({ sessionId }) => openChat(sessionId)} />
```

For a persistent custom shell, mount `useNewConversation` and render
`NewConversationView` with its `creation` result. An optional `createSession`
adapter receives the first message, an idempotency key, and browser choices
(files, model policy, or `startMode: "realtime"`). It returns the session ID;
the server still owns agent configuration, access, and application records.
For voice-first calls the first-message argument is empty. Do not manufacture
a prompt in the adapter.

The stock controller retains the exact in-flight request and adapter when an
outcome is unknown. Retry checks that request instead of creating another chat
from newer edits. A typed `OpenGeniApiError` with `outcomeUnknown: false`
releases a definitively rejected attempt. `onCreated` receives newer unsent
content in `draft`: pass it as `composerOptions.initialDraft` to the selected
conversation. The real server draft supplies its persistence revision. It also
receives `realtimeModel` for the optional voice-autostart handoff. `OpenGeniChat`
already handles both. New uploads added during creation must finish, be retried,
or be removed before the stock view switches to the created chat.

`scopeKey` resets a controller's new draft when your host record changes. Changing
scope or unmounting never cancels a server-side creation or navigates another
scope to its late result. The controller holds active attempts in memory, not
in browser storage; a custom server with durable creation recovery should keep
its ordinary session discovery/reconciliation on the server. Browser markers
are not authorization. Keep the controller mounted for layout changes, and
remount on a signed-in user or tenant change.

`NewConversation` and `NewConversationView` accept `labels` for pending/retry
and upload-handoff copy. In `OpenGeniChat`, use `newChatPending`, `newChatRetry`,
and `newChatFinishingUploads` in `labels`.

## Brand it

`compiled.css` is scoped to the components and needs no Tailwind. Out of the box it needs no extra cosmetic host CSS. To match your product, override the `--og-*` CSS variables on any ancestor:

```css
.assistant-panel {
  --og-color-accent: oklch(0.55 0.2 280);
  --og-color-bg: #ffffff;
  --og-font-sans: "Inter", system-ui, sans-serif;
  --og-radius-md: 8px;
}
```

Dark is the default. Add `data-og-theme="light"` for the light theme and `data-og-density="compact"` for narrow panels:

```tsx
<aside className="assistant-panel" data-og-theme="light" data-og-density="compact">
  <SessionConversation sessionId={sessionId} />
</aside>
```

Menus and dialogs inherit the theme of the element that opened them. See [`tokens.css`](https://github.com/Cloudgeni-ai/opengeni/blob/main/packages/react/styles/tokens.css) for every token.

## Error copy

Error notices use neutral, brand-free text. To prefix or rewrite them, pass `formatError` to the provider:

```tsx
<OpenGeniProvider
  client={client}
  workspaceId={workspaceId}
  formatError={(_error, defaultMessage) => `ACME Assistant: ${defaultMessage}`}
>
  <OpenGeniChat conversationProps={{ toolRegistry }} />
</OpenGeniProvider>
```

An `ErrorMessageFormatter` has the signature `(error: unknown, defaultMessage: string) => string | undefined`. Returning `undefined` or an empty string, or a throwing callback, keeps the default. It receives the original error, so don't log it in the browser.

Outside React, `formatErrorMessage(error, fallback?)` from `@opengeni/sdk` returns the same display text. Show that, not `error.message`.

## Render your tools

Calls to your own MCP server can render as product UI. Tool names are `<server id>__<tool name>`:

```tsx
import { createDefaultToolRegistry, type ToolRendererProps } from "@opengeni/react/session-ui";

function TicketTool({ item }: ToolRendererProps) {
  return <TicketCard call={item} />; // item.arguments, item.output, item.status
}

const toolRegistry = createDefaultToolRegistry({
  entries: [{ match: "name", name: "acme__get_ticket", render: TicketTool }],
});

<SessionConversation sessionId={sessionId} toolRegistry={toolRegistry} />;
```

## Start sessions from the browser

New chats go through the proxy's `createSession` hook. The browser sends the first message and permitted choices; your hook returns the full request, so tools, skills, and authority stay on your server:

```ts
createSessionProxyHandler(og, {
  resolve,
  createSession: (input) => ({
    ...input,
    agent: { capabilities: "none" }, // see Configure the agent
    mcpServers: [{ id: "acme", url: ACME_MCP_URL }], // see Give the agent your data
    tools: [{ kind: "mcp", id: "acme" }],
    sandboxBackend: "none",
  }),
});
```

The proxy carries the browser's idempotency key through unless the hook provides
its own. Voice-first creation includes `startMode: "realtime"`, with no initial
message or first-message files. The same value reaches `beforeForwardMessage`
so an admission hook can distinguish empty creation from a text turn. Model
choices still require the proxy's `modelSelection` option; live voice still
obeys its `realtimeVoice` gate.

## Links, artifacts, and Sites

File links download by file ID. Set `sandboxFiles: true` on the proxy to let users download files from the session's sandbox.

To open artifacts and Sites, either route them to your own pages with `resolveLink`, or enable the proxy's `artifacts: true` and render `SessionArtifactViewer` from `@opengeni/react/artifacts` in `onOpenArtifact` (members need `artifacts:read`).
