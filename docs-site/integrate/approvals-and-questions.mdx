A session can pause mid-turn and wait for a person in two ways. `SessionConversation` renders both inline, and the same turn continues once someone answers. See [Approvals and human input](/concepts/approvals-and-human-input) for the full model.

## Require approval for tools

Set `requireApproval` on a per-session MCP server: `true` for every tool, or a list of tool names:

```ts
mcpServers: [
  {
    id: "acme",
    url: "https://api.acme.com/mcp",
    headers: { Authorization: `Bearer ${token}` },
    requireApproval: ["update_ticket", "refund_order"], // reads run freely; writes wait
  },
],
tools: [{ kind: "mcp", id: "acme" }],
```

The list uses the original names returned by the MCP server's `tools/list`, such as `update_ticket`, not the model-facing `acme__update_ticket` name. API Integrations use a different list: install-time `autoApprovedTools` takes exact compiled `preview.tools[].id` values, and a session MCP policy does not override it. See [Your data](/integrate/your-data).

When the agent proposes a gated call, the session enters `requires_action` and the conversation shows the call with Approve and Reject. A rejection goes back to the agent as the tool's result so it can adapt. Approvals are human-only: an agent can never approve a tool call.

## Let the agent ask questions

Agents have a built-in tool for questions that need an answer before the turn can continue: free text, single select, or multi select, up to 20 per request. Answers are delivered to the agent as the tool's output. To turn it off, set the workspace setting `agentHumanInputEnabled: false`.

## Answering without the React UI

| Surface     | Approve or reject      | Answer a question                                         |
| ----------- | ---------------------- | --------------------------------------------------------- |
| SDK         | `sendApprovalDecision` | `listHumanInputRequests`, then `submitHumanInputResponse` |
| Chat facade | `chat.respond(...)`    | `chat.respond(...)`                                       |

Custom React UIs can use `projectPendingApprovals` and `useHumanInputRequests` from `@opengeni/react/session`.

For a non-React/static renderer, fold ordered, deduplicated events: `session.requiresAction` replaces the pending set, `user.approvalDecision` removes its `payload.approvalId`, and settlement clears the owning turn's pending requests. Preserve each original `payload.approvals[].id` and the decision event ID; reload/replay must not make decided cards actionable again. Send that approval ID to `sendApprovalDecision`, not the requires-action event ID or a generated UI ID. Current requests expose stable `id`, `name` and `arguments`; use the packaged normalizer for older compatibility fields.

Show the exact operation, target and arguments before enabling Approve. In a title-only OpenAPI operation, the proposal may be JSON-string `arguments` containing `body.title`, not a top-level `title`. Parse against that operation's schema and render escaped text. Missing or malformed exact proposal means disabled Approve, not an enabled button beside “proposal unavailable”; Reject or refresh can remain available. Backend/provider ownership, field restrictions and expected-version checks still apply.

Persist a stable `clientEventId` before sending a decision and retain its returned event. Acceptance is not proof that the tool write finished. If `outcomeUnknown` is true, or acceptance is followed by failed local persistence, reconcile durable events and the authorized provider record before any supported exact-request retry. Do not promise “unchanged” or recreate/replay an approval blindly. A stale/no-pending conflict calls for refreshing state. Return friendly host-branded errors; keep raw SDK/provider messages and redacted diagnostics server-only. The full [client Skill](/reference/opengeni-client-skill) includes tested projection, proposal and safe-notice examples.

If a user sends an ordinary message while a session waits, the pending approval or question is cancelled and the message is delivered as a Steer. "Actually, do this instead" is one action.

To notify people who are not watching, subscribe a [webhook](/guides/webhooks-and-credentials#webhooks) to `session.requiresAction` and `session.humanInput.requested`.
