The agent reaches your product through tools you expose. Opengeni calls them; your API authorizes every call.

| Use                                      | When                                                                      |
| ---------------------------------------- | ------------------------------------------------------------------------- |
| **Your tools with the proxy (Node)**     | Your backend mounts the session proxy. Add one `toolServer` option        |
| **Per-session MCP server (any backend)** | You mint and rotate a per-user token yourself                             |
| **OpenAPI Integration**                  | You already have an HTTP API. Opengeni compiles its operations into tools |

A session only sees tools it selects. The proxy's `toolServer` and a per-session `mcpServers` entry select themselves; workspace integrations need `tools`.

## Your tools with the proxy (Node)

The session proxy attaches your MCP endpoint to every chat, mints a short-lived token for the signed-in user, and refreshes it on every message, approval, and answer.

<Steps>
  <Step title="Add toolServer to the proxy">
    ```ts
    createSessionProxyHandler(og, {
      resolve,
      createSession,
      toolServer: {
        url: "https://app.example.com/api/mcp", // public HTTPS
        approvals: { ask: ["rename_post"] }, // the user approves each call
      },
    });
    ```

    You can set `OPENGENI_TOOL_SERVER_URL` instead of `url`. Tools not in `approvals.ask` run without asking; `ask: true` gates every tool. Tools act as the user who started the chat.

  </Step>
  <Step title="Serve your tools, scoped to the verified user">
    With the official MCP SDK (`bun add @modelcontextprotocol/sdk zod`):

    ```ts
    import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
    import { WebStandardStreamableHTTPServerTransport } from "@modelcontextprotocol/sdk/server/webStandardStreamableHttp.js";
    import { ToolRequestError, verifyToolRequest } from "@opengeni/sdk/tool-auth";
    import { z } from "zod";

    export async function mcp(request: Request): Promise<Response> {
      let user: string;
      try {
        ({ user } = await verifyToolRequest(request)); // checks aud = OPENGENI_TOOL_SERVER_URL; or pass { audience }
      } catch (error) {
        if (error instanceof ToolRequestError) return error.toResponse(); // 401
        throw error;
      }
      const server = new McpServer({ name: "acme", version: "1.0.0" });
      server.registerTool("search_posts", { description: "Search the user's posts", inputSchema: { query: z.string() } },
        async ({ query }) => ({ content: [{ type: "text", text: JSON.stringify(await db.posts.search(user, query)) }] }));
      server.registerTool("rename_post", { description: "Rename one of the user's posts", inputSchema: { id: z.string(), title: z.string() } },
        async ({ id, title }) => ({ content: [{ type: "text", text: JSON.stringify(await db.posts.rename(user, id, title)) }] }));
      const transport = new WebStandardStreamableHTTPServerTransport({ enableJsonResponse: true });
      await server.connect(transport);
      return await transport.handleRequest(request);
    }
    ```

    Mount it next to the proxy: in Next.js, `export const POST = mcp; export const GET = mcp;` in `app/api/mcp/route.ts`; in Express, `app.all("/api/mcp", toNodeMiddleware(mcp))` from `@opengeni/sdk/express`; in Hono, `app.all("/api/mcp", toHonoHandler(mcp))` from `@opengeni/sdk/hono`.

    Scope every query to the verified `user`. A record id from the model is only a lookup key: `rename_post` must refuse a post the user does not own.

  </Step>
</Steps>

A runnable Express version is in [`examples/tool-server`](https://github.com/Cloudgeni-ai/opengeni/tree/main/examples/tool-server).

<Accordion title="Verify the token from Python, Rails, Go...">
  It is an HS256 JWT in `Authorization: Bearer` with `iss` `"opengeni-session-proxy"`, `aud` your tool server URL, `sub` the user id, and optional `tenant`. Print the signing key once with `await deriveToolTokenKey()` from `@opengeni/sdk/tool-auth` and store it as `OPENGENI_TOOL_TOKEN_KEY` in the other service.

```python
key = bytes.fromhex(os.environ["OPENGENI_TOOL_TOKEN_KEY"])
claims = jwt.decode(token, key, algorithms=["HS256"], issuer="opengeni-session-proxy",
                    audience="https://app.example.com/api/mcp")  # PyJWT
user, tenant = claims["sub"], claims.get("tenant")
```

</Accordion>

## Per-session MCP server with a per-user token (any backend)

With a [Django or Rails proxy](/integrate/proxy-from-any-backend), attach the server and rotate its token yourself.

<Steps>
  <Step title="Attach and select the server when creating the session">
    ```ts
    const acme = (token: string) => ({ id: "acme", headers: { Authorization: `Bearer ${token}` } });

    await og.client.asUser(user.id, { source: og.source }).createSession(workspaceId, {
      initialMessage,
      idempotencyKey,
      mcpServers: [
        {
          ...acme(await mintUserToken(user)),
          url: "https://api.acme.com/mcp",
          allowedTools: ["get_ticket", "update_ticket"],
        },
      ],
      tools: [{ kind: "mcp", id: "acme" }], // required: select the server
      firstPartyMcpTools: [],
      sandboxBackend: "none",
    });
    ```

    Header values are encrypted at rest and never returned.

  </Step>
  <Step title="Rotate the token on every message">
    `beforeForwardMessage` runs on your server before each message. Return a fresh token and any per-message context:

    ```ts
    createSessionProxyHandler(og, {
      resolve,
      beforeForwardMessage: async (_message, { user }) => ({
        mcpCredentialUpdates: [acme(await mintUserToken(user))],
        modelContext: `Today is ${new Date().toISOString().slice(0, 10)}. Current page: tickets.`,
      }),
    });
    ```

  </Step>
  <Step title="Authorize every call in your MCP server">
    Validate the token and derive the tenant and user from it. Check that every record id the model sends belongs to that user.
  </Step>
</Steps>

Make the token outlive one turn; agents can work for many minutes. `modelContext` is visible to the model and in audit events, so keep secrets out of it.

## Securing the tool token

- Don't reuse the ordinary host login JWT. Use a separate signing key/token namespace with its own issuer/audience, a short expiry, and the narrowest operation scope.
- Your ordinary host endpoints must reject the tool token, and the tool server must reject login tokens. Test both, including account/password/admin APIs.
- Check current user status and record ownership on every call, so a disabled or downgraded user loses access immediately.
- Tool allowlists and approvals limit what the agent tries; only your authorization limits what it can do.

To require approval before a tool runs, set `requireApproval: true` on the server, or list tool names. See [Approvals & questions](/integrate/approvals-and-questions).

## OpenAPI Integration

Publish a focused OpenAPI 3.0 or 3.1 document with only the operations the agent may use. Preview it, choose the operations, and install the revision you reviewed:

```ts
const source = { kind: "openapi" as const, url: "https://api.acme.com/agent-openapi.json" };
const preview = await og.previewApiIntegration(workspaceId, { source, connectionId });
const installed = await og.installApiIntegration(workspaceId, {
  source,
  connectionId, // from og.createConnection(): the credential used to call your API
  expectedRevisionId: preview.revisionId,
  expectedContentSha256: preview.contentSha256,
  instanceKey: "acme-api",
  // Tool ids from the preview, for example every non-destructive one:
  allowedTools: preview.tools
    .filter((tool) => tool.safety !== "destructive")
    .map((tool) => tool.id),
});
// Persist installed.serverId, then select it per session:
// tools: [{ kind: "mcp", id: installed.serverId }]
```

Integrations belong to a workspace, so any session there can select them. Use them for [background agents](/integrate/background-agents). GraphQL endpoints and workspace MCP connections are also supported.

## Reachability

Tool servers and APIs must be public HTTPS URLs. You can pass an OpenAPI document inline (`kind: "openapi_document"`), but the API itself must still be reachable. For local development, tunnel only the tool endpoint, never the whole app: a tunnel to your dev app's port (`cloudflared tunnel --url http://localhost:3000`) publishes every page, including sign-in and admin. If the tool server runs on its own port, tunnel that port; otherwise run a small forwarder that passes only the tool path and tunnel its port (copy-paste snippet under "Local development" in `references/tools-and-auth.md` of the [client skill](/reference/opengeni-client-skill)).

## Keep the tool surface small

Tool schemas cost prompt tokens on every turn. Use `allowedTools` to expose only what you need, and gate writes with approvals.
