Webhooks tell your backend what happens in a workspace, so you don't need to poll. A credential provider lets your backend hand each run short-lived credentials, so you don't store long-lived secrets in Opengeni. Set both up in **Settings > Developer** for one workspace, or **Organization settings > Developer** for all shared workspaces. Both are also available through the API and `@opengeni/sdk`.

|                 | Webhooks                                                                 | Credential provider                                                       |
| --------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| Direction       | Opengeni to your backend                                                 | Opengeni asks your backend                                                |
| When            | A turn finishes or fails, the agent needs input, status or usage changes | Before a run starts, and before its credentials expire                    |
| You answer with | Any 2xx                                                                  | Environment variables, files, Git or MCP credentials, or `not_applicable` |

A workspace's own credential provider replaces the organization's for that workspace. Organization settings can target every shared workspace or only those your product created.

## Signatures

Every request carries an `OpenGeni-Signature` header: an HMAC-SHA256 over the timestamp and raw body. The signing secret is shown once when you create the webhook or provider. Verify the raw body before parsing it:

```ts
import { verifyCredentialProviderRequest, verifyWebhookEvent } from "@opengeni/sdk";

const { event } = await verifyWebhookEvent({ body: rawBody, headers, secret: webhookSecret });
const request = await verifyCredentialProviderRequest({
  body: rawBody,
  headers,
  secret: providerSecret,
});
```

Both throw `OpenGeniSignatureError` for a bad or stale signature. Map the verified `workspaceId` to your own customer to authorize the request.

## Webhooks

The body is a small event; fetch details through the API:

```json
{
  "id": "…",
  "type": "turn.completed",
  "workspaceId": "…",
  "sessionId": "…",
  "turnId": "…",
  "sequence": 42,
  "occurredAt": "2026-10-01T10:00:00.000Z",
  "data": { "status": "idle" }
}
```

- Delivery is at least once and may be out of order. Skip `id`s you've handled, and order by `sequence` within a session.
- Non-2xx responses are retried with backoff. Each webhook's page lists recent deliveries and can resend one.
- **Send test event** posts a signed `webhook.test` event.

## Credential provider

Before a run's first command, Opengeni sends your endpoint a signed `credentials.request` with the workspace, the run, and who started it. Reply within the timeout (10 seconds by default):

```json
{
  "status": "ok",
  "environment": { "AWS_ACCESS_KEY_ID": "…", "AWS_SECRET_ACCESS_KEY": "…" },
  "files": [{ "path": "gcp/key.json", "content": "…" }],
  "fileEnvironment": { "GOOGLE_APPLICATION_CREDENTIALS": "gcp/key.json" },
  "git": [{ "host": "github.com", "password": "ghs_…" }],
  "expiresAt": "2026-10-01T12:00:00Z"
}
```

Or reply `{ "status": "not_applicable" }` or `{ "status": "auth_needed", "authNeeded": [...] }`. The values reach the sandbox only, not the conversation or logs. Opengeni asks again before `expiresAt`.

**Test connection** sends a request with `purpose: "test"` and shows which names a run would get.

The full protocol is in the [integration reference](https://github.com/Cloudgeni-ai/opengeni/blob/main/docs/workspace-integrations.md).
