# Provider failure audit — 1 October 2026

Source baseline: `6a97313448881412fca5e610fb2821b308f53b30` (main). Tracking: [OPE-630](https://linear.app/cloudgeni/issue/OPE-630/audit-provider-failure-contracts-and-fix-quota-unknown-stream-and), under [OPE-546](https://linear.app/cloudgeni/issue/OPE-546/errors-and-retries).

## Finding and scope

Coverage is partial. OpenGeni already distinguishes safety, quota, throttling, connectivity, context exhaustion, subscription authentication and authoritative sandbox loss. The audit found documented codes we missed, an invented retryable status for unknown Claude stream errors, and raw diagnostics in the web failure headline. This change fixes those specific cases. It does **not** certify every provider, every endpoint, or every SDK version.

The scope is configured **turn inference** and the complete 12-backend sandbox registry. Media generation, transcription, embeddings, object storage and third-party MCP services have separate endpoint contracts and are not certified by this audit. Research used official error, streaming, lifecycle and SDK references; links below are the evidence, not a claim to have read every page on each vendor's website. Generic customer-configured endpoints cannot have a finite vendor inventory. Subscription proxies need their own compatibility evidence; public API documentation does not fully specify them.

No live paid inference or destructive sandbox fault injection was performed. Existing incident evidence established a Modal task-router DNS/transport failure with uncertain command outcome, and a separate Codex empty HTTP 400. Neither proves that OpenGeni caused the upstream failure. An empty 400 also does not prove entitlement loss, bad user content, or a provider outage.

API-key OpenAI/Azure/compatible clients use the configured SDK retry budget (default 5); exhausted quota vetoes these retries when the upstream has not supplied an explicit `x-should-retry` directive. The existing directive exception needs conformance review. Gateway/OpenRouter/Codex/SuperGrok clients use zero SDK retries. Runner-managed Responses recovery also disables SDK retries. Native Claude uses fetch, not Anthropic's SDK retry defaults. Worker request recovery is bounded and cannot authorize replay of a whole side-effectful turn. Existing fences for partial output, tool receipts, command outcome and writer quiescence remain authoritative. Vendor advice to retry a request is not permission to repeat a tool or create a second sandbox.

## Target failure/message contract

This is the required coverage checklist for subsequent work, **not a claim every row is implemented everywhere**. A typed category must come from the owning protocol/operation. Keep the raw accepted event/history and diagnostic evidence intact; presentation may summarize it. Remedies must match the viewer's authority and current execution state.

| Failure class | Appropriate headline/remedy | Recovery rule |
| --- | --- | --- |
| Credential rejected/expired | “The model provider rejected the credentials for this model.” Reconnect/fix credentials when authorized. | One established refresh flow only; no blind repeated bad-key requests. |
| Access/region/RBAC/model permission | “The model provider denied access to this model.” Point to the actual owner/configuration. | No transient retry from 403 alone; safety codes take precedence. |
| Credits, daily allowance, monthly spend, hard quota | Name the proven limit; offer top-up/owner/model actions actually available. | Stop automatic retries; do not invent a reset time or switch billing sources. |
| Short throttle/ramp limit | Explain that the provider is limiting requests; show truthful waiting state. | Honor Retry-After/Retry-After-ms at the safe request boundary, within the existing budget. |
| Overload/temporary unavailable | State temporary provider unavailability when typed evidence supports it. | Bounded safe recovery; inspect partial output and accepted tools before redispatch. |
| Invalid input/config/unsupported parameter | “The provider could not accept this request.” Distinguish editable user input from deployment configuration when known. | Same unchanged request cannot resolve validation; unknown/empty body cannot establish cause. |
| Context/request too large | Explain input/context limit and supported compaction/remedy. | Use existing protocol-preserving compaction; never discard accepted content silently. |
| Safety/refusal | “The model provider declined this request.” | No automatic retry or account/model rotation to evade a refusal. |
| Empty/malformed body or unknown stream code | “The session stopped because of an unexpected error.” Known Codex empty rejection names Codex. Keep diagnostic Details. | Unknown classification remains conservative; no invented 502 or successful terminal. |
| DNS/TLS/reset/stream cut-off | Explain connection interruption without claiming who caused it. | Transport failure after dispatch can leave effects uncertain; re-observe the same identity. |
| Sandbox definitely gone | Explain execution environment loss and available recovery/cold-start implications. | Only authoritative sandbox-scoped evidence licenses replacement and lost-command settlement. |
| Sandbox auth/quota/image/unsupported feature | Name connection, resource allowance, image setup or unavailable capability when proved. | Owner/configuration fix; do not repeat create/restore mutations blindly. |
| Command exit nonzero | Explain that the command failed, with exit/output available. | Return a command result; not automatically a failed provider/session. |
| Command/readiness timeout, poll failure | Explain the operation deadline or observation interruption; state uncertainty when applicable. | Timeout is not termination; retain command identity and durable effect fences. |
| Cancellation/wait/pause | Use the existing interrupted/waiting/paused status. | Preserve explicit user intent; do not label these provider outages. |

Technical request IDs, RPC paths and stack traces belong behind diagnostic disclosure, not in the main headline. Unknown failures still need a useful generic message. A pretty message must not enable unsafe Retry or remove a structural recovery blocker.

## Changes and verification in this candidate

- Closed OpenAI credit/monthly-limit codes are recognized before wording heuristics and before the SDK quota retry veto (subject to its existing explicit-directive exception). Responses ramp/overload codes retain their documented recovery class; misalignment refusal is safety in both HTTP and SSE paths.
- Claude's documented spend proof is retained as a closed code, preserving the adapter's existing restriction against copying arbitrary provider bodies. Ordinary 429/529 stay recoverable. A spend prefix quoted inside another validation error does not become quota authority. Unknown stream errors, including inherited object property names, receive no synthetic HTTP status. Claude payment refusals have a separate terminal billing code.
- A real non-429 HTTP refusal dominates rate-limit words in the worker classifier. Azure millisecond retry headers survive the semantic Responses exception boundary and are honored by worker delay selection.
- Stock web banners preserve native Claude credential remedies, distinguish payment errors from exhausted credits, and summarize empty Codex rejection, Modal router interruption and otherwise unknown uncoded failures. Details retain complete recorded diagnostic whitespace. OpenGeni credits, safety and other authored worker codes keep their existing special handling.

The initial scripted regression set failed all 10 cases against the baseline. Fixtures exercise HTTP and SSE without paid models, then pass through the actual adapter and worker classifier. Existing quota, semantic terminal, Claude protocol, tracing and banner/action tests also run. Package typechecks cover runtime, worker and web. Review/validation results are recorded on OPE-630 and the PR; no deployment is implied by a green unit test.

## Remaining work, in priority order

1. **Shared user presentation:** React timeline still combines raw diagnostics with the headline. Introduce a common typed presentation carrying headline + details and adopt it in web, embedded React and SDK examples. Include preclaim failures and current failure frontier. Preserve complete diagnostics and existing structural Retry blockers. This audit improves the stock banner only.
2. **OpenRouter/compatible semantic errors:** test HTTP 200 error JSON, top-level SSE errors, `metadata.error_type`, `finish_reason: error`, EOF after partial output/tool calls, and reasoning-token exhaustion. Also cover non-stream Responses failed/incomplete results and native Claude's newer stop reasons. Assert no false success, no invented transient class, no duplicate tool/usage dispatch.
3. **Sandbox conformance and actionable categories:** inventory installed optional SDK versions and nested retries, then fixture every backend's create/resume/exec/poll/snapshot/terminate phases. Prioritize Blaxel's unavailable-404 and all post-dispatch timeouts. Add distinct auth/quota/image/resource/unsupported/unknown-outcome user messages without weakening loss proof. Modal transport/root-cause work remains [OPE-13](https://linear.app/cloudgeni/issue/OPE-13).
4. **Production acceptance:** deploy through the normal release process, repeat the existing production failure sweep, and verify each enabled integration with safe read-only/controlled fixtures. Unit tests and documentation review alone cannot confirm provider outages, current DNS health, upstream charges or recovery under real service failure. OPE-546 remains open.

Admission-block UI verification and existing retry/goal defects already tracked separately are not declared fixed here. Scheduled monitoring is not created by this audit. Re-audit when an endpoint, provider, API version, SDK or documented error grammar changes; add an official reference and a failing fixture before granting any new retry or loss authority.
