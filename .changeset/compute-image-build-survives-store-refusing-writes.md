A compute host whose object store refuses writes, or is out of reach, no longer throws away the sandbox images it builds. Before, a build whose last step (storing the image) failed was discarded, the next ask built it again from scratch on another host (close to an hour per build on a slow store), and each of those builds failed the same way. Now the host keeps the image it built in its own image cache, so it serves it without a fetch, and tries the store again in the background, waiting 30 seconds and then twice as long after each failure, up to 10 minutes. While it does, the control service hears that the build is under way and keeps creating sandboxes from the image it used before; as soon as the store takes writes again the image is stored and new creates start from it, without another build. The kept copy is an ordinary cached image, so disk relief can remove it when the host needs the room (the image is then built again), and the host stops trying once the control service has not asked for the image for 30 minutes.
