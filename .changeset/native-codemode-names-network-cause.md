The native Codemode client on Connected Machines (`opengeni-agent codemode`, the `$OPENGENI_CODEMODE_NATIVE_CLIENT` path) now says why it can't reach Opengeni instead of "Codemode request failed: error sending request for url (…)". A failed DNS lookup names the host, the resolver's reason and where to look; a TLS certificate that is not yet valid or has expired names this machine's clock reading, so a wrong clock is easy to spot; a certificate for another name points at the URL and intercepting proxies; a refused, timed-out, closed or unroutable connection says so. When a proxy from `HTTPS_PROXY`, `HTTP_PROXY` or `ALL_PROXY` is in use, connection failures name the proxy (host and port only) and its variable instead of blaming Opengeni's host or the resolver, and a failure while an answer was arriving reads "Lost contact with Opengeni". A connection that is not up within 10 seconds now fails as a connection timeout instead of waiting out the 30-second request limit. The machine's own settings are never changed: on a person's own computer the message says what to check. Unknown causes keep the previous text. Takes effect with the next machine agent release (0.1.151).
