Connected Machine agent updates now target only a published release and stop waiting forever for open browsers. Unpinned, a deployment followed its source tree's agent version, which is raised when an agent change lands and published later, so machines were asked to install a release that did not exist yet and failed with `manifest_download_failed`. The API now checks that the release's signed manifest exists and otherwise targets the newest published patch release below it; a pinned version is used as set. A retryable failure such as a failed download is retried after 10 minutes, then after as long as the machine has been failing to update, up to 6 hours, instead of hourly. An agent older than 0.1.58 closes its managed browsers when it updates, so its automatic update used to be postponed whenever any browser was open, which on a shared machine could be forever. Now browsers whose sessions have no turn underway do not hold the update. If browsers stay in use for a day, the next postponement announces a closing time 30 minutes later, every browser observation an agent gets from that machine says when its browser will close, and the update is requested then. Migration 1270 adds `enrollments.agent_update_pending_since`, which keeps when the current run of unsuccessful attempts began.
