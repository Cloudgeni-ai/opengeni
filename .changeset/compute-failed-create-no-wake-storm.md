Retrying a compute sandbox create whose host failed it no longer floods that host with wake requests. Before, a create that failed on the host (for example, because the host could not fetch the image) left the sandbox recorded as being on that host. Every retry of the create, with the same request id, then asked the host to wake it, and the host kept answering that it had no such sandbox. The control service asked again every 250 ms until the wake gave up after a minute and answered "unavailable". The client retried that too, so one failed create became minutes of waiting and hundreds of wake requests. Now, once the host's answer is final (no create can still reach it), the sandbox was never confirmed on any host, and it has no archive, the control service knows it exists nowhere. It forgets the sandbox at once: the retry makes the create again under the same id, so it either succeeds or fails right away with the host's own error, and a wake of that sandbox answers "not found" at once.
