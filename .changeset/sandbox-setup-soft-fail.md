A workspace machine the agent damaged no longer fails every later turn during platform setup. Before, when a step of the setup that runs at the start of every turn failed because of the box itself (for example `/workspace` was full, or `/workspace/.opengeni` had been replaced by a file), the turn stopped before the model ran, and because the box's saved copy kept that state, every later turn stopped the same way. Now the run credential files, the Codemode client and token, repository setup, Azure CLI sign-in and the document tools check fail softly when the cause is the box's own state (no space, a used-up quota, a read-only file system, a blocked path or denied permission reported by a file operation, or a setup command that exited with an error): the turn starts, and the model gets one short notice naming what failed, the cause and what to do, for example "No space left on the workspace machine's disk. Free space in /workspace or /tmp …; then they are installed again at the start of the next turn". The notice is added to the turn's input before the model runs, including when the worker started setup before the input was ready; only when the workspace machine is set up lazily by the first tool call does it follow the next shell command's result, through the same setup notices as a repository folder moved aside. A setup command's failure is read from the command's own exit and output, never from words in an unrelated error, and a repository or Azure sign-in failure tells the model to run git or `az login` itself to see the error. Setup still fails as before when the attempt was cancelled, the machine agent did not answer, the machine cannot start programs (including a Modal box whose `/bin/sh` is gone), a setup command timed out, or the cause is not recognised, so the existing recovery for those keeps working.
