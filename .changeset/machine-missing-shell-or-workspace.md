A machine whose `/bin/sh` or workspace folder was moved away keeps running commands. Before, after a command ran `mv /bin/sh …`, every later command failed with "not found: spawn or apply execution containment …", even after a restart, because the disk keeps the change; and after `/workspace` was moved away, every command failed with "not found: exec working directory /workspace" and the turn stopped until a later turn's setup made the folder again. The machine agent (0.1.153) now starts dash or bash when `/bin/sh` is missing or not executable and, running as root on Linux, points `/bin/sh` back at it. When it cannot restore the link, commands still start the fallback. A missing workspace root or home folder used as a command's working directory is created again, empty, and the command runs; placeholder homes such as `/nonexistent` and other missing folders still fail as not found. When no shell is left at all, the error says "the shell /bin/sh is missing and no dash or bash was found", the tool output says a restart does not bring the shell back, and on a Connected Machine the turn stops with "Your connected machine can't start programs because /bin/sh is missing. Put it back on the machine, then retry."
