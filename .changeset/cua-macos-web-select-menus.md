On macOS, observing a window whose app is too busy to answer accessibility (some apps are while they show a menu) no longer fails with a server error after 7 s. CUA now bounds the requests that find the window by the read's time budget, and the observation comes back with the screenshot, marked as cut short because the app answered too slowly, while refs from the last reading keep working. A web `<select>` in a WebKit view (apps that embed a WKWebView) now works while its menu is open: `set_value` picks the option by name from the open menu (or opens it, picks and closes it), uses an open menu only when its chosen item lies over that select (never a neighbouring select's menu), and checks the select shows the option afterwards. Invoking one of the menu's items is accepted instead of being refused as outside the window, and pointer or key input to it is refused with a message that names the open menu. The first reading of a WKWebView window no longer omits the web page: an element that times out once is asked again, and in a timed reading one that never answers marks the reading as cut short instead of disappearing.
