Voice commands: a person can call a chosen chat by name. `adapter.setCallCommands([{ id, workspaceId, sessionId, name }])` stores the chats they picked natively. On iOS the generated start-call App Intent gains an optional chat parameter whose entities are exactly those commands, with new parameterized App Shortcut phrases (`call.chatPhrases`, default `"Call {chat} in {app}"` and `"Talk to {chat} in {app}"`), and the app's App Shortcuts are refreshed whenever the commands change and at launch. On Android each command becomes a dynamic launcher shortcut, and `adapter.pinCallCommand(command)` pins one to the home screen. Start requests now carry an optional `workspaceId` (and a `requestId`), and `callFromOutside(sessionId, workspaceId)` calls a session in another workspace of the signed-in account. Pending start requests are kept until JavaScript takes them (up to a minute), so a request that launched the app is no longer lost to an early listener. The start-call intent now requires an unlocked device (`.requiresAuthentication`), and `INStartCallIntent` requests from a locked phone (Phone recents, "call … using") wait for an unlock for up to 30 seconds and are otherwise dropped (iOS reports a passcode-protected phone as locked about 10 seconds after its screen locks). CallKit handles for a named session are now `"<workspaceId>/<sessionId>"`; bare session handles from older recents still work.
