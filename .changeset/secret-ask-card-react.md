Human-input cards answer `kind: "secret"` questions. The field is an uncontrolled password input read only at submit, so the value never enters React state, props or storage, and it is cleared after a successful submit and on unmount. It pairs an optional username with the password for password managers, sets `autocomplete` from the spec (`new-password` when Generate is allowed, `one-time-code` with a numeric keyboard for one-time codes), offers show/hide and Generate (filled in the browser with a `SecretsUiProvider` generator, otherwise generated by the server with Undo), shows the `looksLike` hint and a soft, non-blocking pattern warning, and has a Save to select (Only me, This task, This workspace). New `allowedSaveTo` prop on `HumanInputForm` and `HumanInputSurface`: a requested target outside it falls back to the most private allowed one with a note. Submit sends `secretAnswers` next to `answers`. Answered secret questions show "Saved to <vault> › <item>", never a value. Secret references (`{{secret:…}}`, `{{secretfile:…}}`) render as chips in Markdown prose and whole-reference inline code (never in fenced code or links), tool payloads and commands, tool row titles and approval review fields, when a `SecretsUiProvider` is mounted; malformed references stay plain text. New exports `SecretRefChip`, `SecretRefText`, `SecretAnswerChip` and `secretReferenceLabel`, and `SecretsUiProvider` from `@opengeni/react/session-ui`.
