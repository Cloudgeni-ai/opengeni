The composer's repository menu is clearer for someone opening it for the first time. It is for picking repositories: the "GitHub access" section with installs, per-installation links and unlink buttons is replaced by one "Manage GitHub access" row that opens the GitHub settings page, where every installation now also has its own Unlink (installations that are no longer active stay listed there, so they can still be unlinked). A switched-on repository says who it acts as ("Acts as You (@login)" or "Acts as Opengeni app") when your GitHub is connected, instead of an unexplained "As you" pill, and shows its branch once. With nothing connected, the menu offers Your GitHub (Connect) and, on hosted workspaces, the Opengeni app (Install), each with one plain line about what it means; an operator who hasn't created the app yet keeps Create app even when other repositories are listed. Repositories already in a chat show "In chat", with "To change the branch of a repository already in this chat, start a new chat." The menu has no "Refresh list" row any more: it updates in the background when it opens (at most once every 30 seconds), and as soon as you come back from GitHub or the GitHub settings page (for a workspace admin, also syncing from GitHub); a failed load says so with an inline "Try again" and keeps "Manage GitHub access" reachable. Links to other app pages go through the app's navigation, so an embedded session opens them beside the host page. Change repositories on the GitHub settings page opens GitHub through a fresh link, one tab per click. `RepositoryContextPickerProps` gains `githubSettingsUrl` and `onLeaveForGitHub` and drops `githubAppOpen`, `onGitHubAppOpenChange`, `onConfigureInstallation` and `onDisconnectInstallation`; `useRepositoryCatalogRefresh` returns `onLeaveForGitHub`; the app context drops `githubAppOpen` and `setGithubAppOpen`.
