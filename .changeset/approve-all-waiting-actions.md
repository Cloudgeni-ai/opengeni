When two or more actions wait for approval, the approval stack now offers **Approve all** (with the count, for example "Approve all 3") and **Decline all** beside its pager, in the chat and in each sub-session's stack in the parent chat. Each action is still decided on its own through the host's `onApprove` / `onReject`, one after another, so every decision goes through the same request and server checks as its card. Approve all counts only actions whose own card offers Approve without more input: not one only its account's owner may approve, one this person can't access, one that can't be decided yet, or an MCP server's question; Decline all covers every action its card can decline. While it runs, the stack shows "Approving 2 of 3…" and the cards wait. An action that is refused stays waiting, is selected and is named with its error ("Couldn't approve …: …"); the rest keep going. An action decided elsewhere, or whose facts change, is skipped; one that arrives meanwhile waits for its own decision; leaving the chat stops the run. With two or more waiting, `ApprovalSurface` reads each one's review (through `loadReview`) instead of only the selected one's; the selected card reuses that read. New messages: `approvalSurface.approveAll`, `approvalSurface.declineAll`, `approvalSurface.approvingIndexOfLength`, `approvalSurface.decliningIndexOfLength`, `approvalSurface.couldnTApproveTitle` and `approvalSurface.couldnTDeclineTitle`. An action already decided by the run is not offered or sent again while the host still lists it, and one whose review couldn't be read yet is read again. `useSessionControl`'s `approve` and `reject` take an optional last `ApprovalDecisionOptions` argument; `{ throwOnError: true }` rejects with the refusal instead of resolving `null` (`error` is still set), and `SessionConversation` uses it so a refused action is named in the stack.
