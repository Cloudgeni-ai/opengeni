# Agent / automation notes (OpenGeni)

This repository is a clean TypeScript/Bun stack. The public API is session-based.

> **Start here for orientation: [`docs/architecture.md`](docs/architecture.md).** It is the canonical whole-system map — what OpenGeni is, the load-bearing invariants, the full repo layout, per-component deep-dives, and a *"if you're changing X, read Y first"* decision table. Read it before navigating an unfamiliar area, and **keep it current**: if your change adds/removes/renames an app, package, or sandbox backend; alters an architectural invariant, the data-flow, or the session/turn lifecycle; or changes which file is canonical for a change area — update `docs/architecture.md` in the *same* change. A stale map is a bug. (This file, AGENTS.md, owns *how to run and operate* the stack; architecture.md owns *how the system is shaped*.)

When the user says **"start the dev server"**, **"spin it up"**, or **"run the full stack"**, they mean the steps under **Full local stack**.

## Full Local Stack

The stack means everything needed to run the Hono API, React web app, Temporal worker, Postgres event store, Core NATS realtime bus, Temporal service, and configured OpenAI Agents SDK sandbox backend.

1. Start the full local stack:

   ```bash
   bun run dev
   ```

   This installs dependencies, starts the Docker infrastructure, runs migrations, builds the local sandbox image, and starts API, worker, and web processes.

Manual equivalent:

1. Install dependencies:

   ```bash
   bun install
   ```

2. Start infrastructure:

   ```bash
   docker compose up -d postgres nats temporal minio minio-init
   bun run db:migrate
   bun run db:provision-roles
   ```

3. Build the local sandbox image when using Docker sandbox:

   ```bash
   docker build -f docker/sandbox.Dockerfile -t opengeni-sandbox:local .
   ```

4. Copy `.env.example` to `.env` and configure at least:

   - `OPENGENI_DATABASE_URL`
   - `OPENGENI_NATS_URL`
   - `OPENGENI_TEMPORAL_HOST`
   - `OPENGENI_STARTUP_DEPENDENCY_RETRY_*` when dependencies need longer startup windows
   - OpenAI or Azure OpenAI credentials
   - `OPENGENI_SANDBOX_BACKEND` (see Sandbox Notes for the full backend list; `docker` is the default for local dev)
   - sandbox preparation profiles / env allowlist when needed

5. Start long-running processes in separate terminals:

   ```bash
   bun run dev:api
   bun run dev:worker:control
   bun run dev:worker:turn
   bun run dev:web
   ```

   The control and turn workers poll separate Temporal task queues; both must run
   or sessions are accepted but never execute a turn.

Default URLs:

- API: `http://127.0.0.1:8000`
- API health: `http://127.0.0.1:8000/healthz`
- Web: `http://127.0.0.1:3000`
- NATS monitor: `http://127.0.0.1:8222`
- Temporal gRPC: `127.0.0.1:7233`

`bun run dev` is per-worktree: Compose project = directory basename (main checkout dir `opengeni` → `opengeni-main`; override with `OPENGENI_COMPOSE_PROJECT`), free host ports (ignore copied `.env` port pins unless `OPENGENI_PIN_PORTS=1`), rewrite loopback URLs including `nats://`, write `.env.runtime`. `bun run dev:*` / `db:*` source `.env` then `.env.runtime`. Do not reuse another worktree’s host ports. Sandbox image build skips when `OPENGENI_SANDBOX_BACKEND=none`.

MinIO is the local S3-compatible object storage default for Docker Compose and optional self-contained Kubernetes smoke tests. Production deployments should use provider-native storage instead of deploying MinIO manually: `azure-blob` for Azure Blob, `aws-s3` for AWS S3, and `gcs` for Google Cloud Storage.

## Architecture Notes

For a map of every app, package, and how the parts fit together, start at [`docs/architecture.md`](docs/architecture.md) and follow its links to the focused topic docs.

- Public clients talk only to the API.
- Domain/access/billing helpers now live in `@opengeni/core` under `packages/core/src`; `apps/api` routes are HTTP adapters over them.
- Browser streaming uses `GET /v1/workspaces/:workspaceId/sessions/:id/events/stream` with SSE.
- Session goals support `GET`, `PATCH(status paused|active)`, and idempotent `DELETE` clear on `/v1/workspaces/:workspaceId/sessions/:id/goal`; clearing removes the goal row and emits `goal.cleared`.
- Core NATS is the realtime bus between producers and API instances.
- Postgres is the durable event store and replay source.
- Workspace-control events are compact invalidations, not evidence blobs: control reasons and
  actors have canonical UTF-8 ingress/storage bounds, legacy rows carry explicit loss facts, and
  REST/NATS/SSE projections are independently byte-bounded. The rolling storage migration rewrites
  only pre-existing cap violations; already-bounded legacy rows stay untouched with projection-time
  byte facts.
- Temporal is orchestration only. Token streams do not go through workflow history.
- OpenAI Agents SDK execution happens inside non-retryable worker activities.
- Agent activities are side-effectful. Do not add automatic Temporal retries around full agent turns unless each model/tool/sandbox boundary has been made idempotent.
- Codex rate-limit reset credits are never automatic agent capacity. Their
  irreversible consume path is managed-cookie owning-human web-only with durable
  provider idempotency; do not add an SDK, MCP, Toolspace, worker, scheduled, or
  allocator/rotation consume hook. See `docs/codex-subscription-rotation.md`.

## Run Lifecycle (read `docs/run-lifecycle.md` before changing the session workflow, the agent turn activity, or memory)

Three principles here are load-bearing and easy to break by accident:

- **No run-length limits, by design.** OpenGeni runs agents that legitimately work for days. Run length is bounded by symptoms (no-progress detection, budget exhaustion), never by counts or clocks. Do not add or lower caps on model calls per turn, continuation count, or activity timeout as a way to "be safe" — fix the pathology instead. See `docs/run-lifecycle.md` and `docs/goals.md`.
- **Three memory stores, three jobs.** `session_history_items` is protocol-preserving, exact JSON conversation truth fed to the model (default read path); SDK-origin history, pending tool call/result receipts, approval snapshots, and durable event projections pass through one protocol boundary that omits only object properties whose JavaScript value is `undefined` (JSON-wire absence) and rejects every other non-JSON graph with a path. Accepted user, agent, tool, and source content is never regex-scanned or rewritten because it resembles a credential. `agent_run_states` is the serialized RunState blob plus the protocol-normalized approval snapshot, used *only* to resume a turn paused for a human approval — never as conversation memory. `session_events` is the exact append-only human/audit timeline for accepted payloads and must never be fed back to the model; deterministic size/protocol projections are separate from content classification. Sandbox recovery state is separate again in `sandbox_session_envelopes`. Workspace knowledge memory (`knowledge_memories`; the curated docs-MCP lane remains human-reviewed: agents search approved records and propose through its tools) is retrieval context, never conversation memory, and accepted memory text is stored exactly. Its typed workspace/user/role/session/ephemeral selectors are enforced by FORCE RLS; missing context denies, relationship reads require both endpoints, and lifecycle evidence is immutable, exact-actor, and value-free. Scoped knowledge provenance (`knowledge_providers` through immutable claims/evidence/reviews) is separate again: it is RAG evidence rather than prompt state or active memory, uses exactly organization/workspace/initiating-user authority, and proposal rows never activate policy or preferences. Instruction-policy onboarding proposals likewise create only immutable evidence plus an inactive revision in the existing policy authority; they never become a parallel prompt/memory store or activate policy themselves. Do not infer human authority from session creation or provenance metadata, expose legacy scopes to the runtime role, or mutate typed selectors/edges outside the lifecycle functions. See `docs/hierarchical-memory.md`, `docs/scoped-knowledge.md`, and `docs/workspace-instruction-policies.md`.
- **Company profile is its own bounded organization authority.** `company_profile_revisions` plus one active head and immutable activation events own concise identity, mission, products, customers, goals, and constraints. Exact accepted attempts freeze it in `company_profile_snapshots` and the existing workspace-governance composer places it after CORE and before workspace charter/policy. It is not Documents/RAG, Memory, Preference Registry, workspace policy, or another prompt composer; no profile means the prior prompt path remains byte-identical. Organization mutation requires exact account authority, and durable learning reaches it only through the adapter seam in `docs/company-profile.md`.
- **Exact content and configured-secret authority are separate concerns.** Never add a central heuristic/exact-value redactor to model context, history, events, memory, tool calls/results, failures, diagnostics, transcription, or UI data. Configured secrets remain authenticated-encrypted at rest. Plaintext list/read/write is an explicit permissioned operation (`secrets:list|read|write` and `variable-sets:list|read|write|use`), tenant/session constrained and metadata-only audited; audit rows never contain the value. Masking is allowed only at a genuinely public or third-party sink and must not mutate OpenGeni's stored or agent-visible data. Historical bytes already rewritten by older releases are irrecoverable.
- **Goals drive long runs through a Postgres obligation, not workflow polling.** Terminal settlement atomically advances an active goal's monotonic wake revision and the workflow-wake outbox; one transaction materializes that revision as the typed update, events, usage fact, observed revision, session transition, and successor wake. Human/Steer work, approval, recovery, provider waits, recursive Pause, and cancellation remain authoritative. Temporal signals/runs are repairable nudges only. See `docs/goals.md`.
- **Synthesized follow-up turns preserve the effective model policy.** Goal continuations inherit model + reasoning + latency mode from the newest turn that durably emitted `turn.started`, falling back to the session default only when no turn has actually run. A claimed turn rejected during admission must not silently switch the next turn's provider or billing owner. Child terminal results always enter the bounded typed internal-update batch for their parent.
- **Context compaction is one durable transition, mode-frozen per session.** Non-Codex sessions and Codex sessions frozen `portable` use Codex's local plaintext checkpoint: the summarizer sees a protocol-valid temporary copy of active structured history plus the fixed checkpoint prompt; the replacement is newest real user messages in one cumulative 20,000-token budget plus one summary. Codex sessions frozen `remote_v2` (default for new Codex sessions; workspace may opt into `codexCompactionDefault: "portable"`) call Codex remote compaction v2 (`compaction_trigger` + beta `remote_compaction_v2`), persist the opaque `{ type: "compaction", encrypted_content }` item with retained user/developer messages including images (64k budget). The compact request must reuse the ordinary turn prompt-cache prefix (exact agent instructions + model-visible tool schemas; empty instructions rejected; operator `/compact` on `remote_v2` builds the agent first), and admit only Codex models for the session lifetime — fail closed with no portable fallback. Mode is written once at create; existing sessions backfill `portable`. Before the portable provider call, aggregate oversized tool results are replaced oldest-first only in that temporary copy; if needed, whole oldest user-delimited units are removed and the suffix is re-sanitized. One provider overflow permits one smaller refit, never one provider request per item. Provider failure leaves active history unchanged; an empty successful response is a typed failure, while Codex terminal `response.failed`/`response.error` events are bounded provider failures rather than empty summaries. A failed same-turn recovery ends that workflow run without synthesizing another goal continuation from unchanged state. Machine inputs already visible to the model remain delivered in durable history and are never requeued; only genuinely new updates remain pending. A later human/API prompt, Agent Steer, explicitly requested Compact, or genuinely new machine input may create newer truth and retry. There is no deterministic summary, compatibility ladder, ordinary inference-time history trim, SDK `context_management`, or new queue turn. Automatic compaction uses only provider-reported usage bound to the durable prior call or immediately preceding same-activity request; without one, send the request and recover from a genuine provider overflow rather than forcing compaction from a whole-request approximation. Local estimates are limited to fitting the compaction request and reporting history-only replacement sizes, and compaction/context clearing sets `last_input_tokens` to null until a successful ordinary provider response replaces it. The exact current turn-attempt UUID fences both the replacement-history transaction and its token signal. A pending receipt whose complete pair was made inactive by compaction is consumed without reactivation or duplicate output; a still-active complete pair retains its recovery event because the crash may have occurred before the original event publish. Codex subscription model limits are raw/effective/auto-compact 272,000/258,400/244,800.
- **Machine input is durable model memory, not activity-local context.** Agent messages, Agent Steer, child results, schedules, and goal continuations remain individually canonical in `session_system_updates`. Claim atomically binds a bounded coalesced group to one receiving turn and one exact `session_history_items` row before inference. Recovery reuses that row, reconciliation preserves it, and interruption/failure never returns an already-model-visible member to pending. The queue reads pending records directly; events only invalidate it. The timeline uses bounded lifecycle events and stable input ids while unrestricted content stays in canonical storage.
- **Document authority migration 0165 is a drained protocol cutover.** Stop every API and worker, close all `document-index-*` Temporal workflows, and settle every queued/indexing document before migrating; the migration rejects both live `opengeni_app` sessions and an undrained document queue. After it commits, never start an old image. Every new direct or Temporal indexing input carries the exact immutable authority tuple, while rolling migration 0167 permits only bounded historical three-field Temporal replay: resolve the stored immutable tuple under exact account/workspace RLS before any write, and reject every partial or mismatched supplied tuple. Publishing organization-authority content requires an exact account-admin grant rather than workspace-admin expansion.
- **Transient required-MCP transport failures are recoverable without replay.** A connect/tools-list/next-loop MCP request timeout or allowlisted statusless socket failure can escape MCP setup even though thrown tool-call failures are normally converted to `isError` outputs. Required first-party connect/tools-list also treats a rolling replacement's temporary `404` or statusless plain transport `Error` as recovery-safe; this exception never applies to external servers, tool invocation, explicit non-404 client responses, or typed protocol/programming errors. Retry classification is typed out-of-band metadata and does not rewrite the exact source diagnostic retained on internal OpenGeni data paths; only the genuinely public SDK/console projection is fixed structural metadata with no raw URL, body, or transport message. The worker checkpoints conversation truth and recovers the same accepted turn after capped 2 s / 5 s / 15 s / 30 s / 60 s pacing; it never blindly replays a completed tool call, consumes a goal continuation, or manufactures a replacement prompt. Other HTTP client failures and unknown codes remain terminal.
- **Codex history is canonical; credentials are not compatibility identities.** Subscription/model changes never mutate, filter, reclassify, or rewrite `session_history_items` or `agent_run_states`. Responses requests use canonical items directly; a Chat request may build one request-local transcript view for record types that Chat Completions cannot represent. Historical `tool_search` calls/outputs are facts: never rerun, compare with today's tools, or change their execution mode. `remote_v2` compaction is Codex-only; `portable` history may cross supported provider routes through the request adapter.
- **Generated pixels are artifacts, not prompt history.** Native image base64 must be retained and replaced by the closed `generated_image` receipt before durable history/events/RunState; adapter tools return that same receipt. Later native items become a deterministic request-local artifact fact, while adapter history keeps its provider-neutral tool call and compact receipt. The browser and sandbox resolve bytes through the authenticated file/artifact authority. Never put base64, object keys, signed URLs, or provider identities into the durable/model-facing prefix, and never replay an adapter provider call after its durable started fence. See `docs/image-generation.md`.
- **Codex opaque-artifact rejection preserves durable truth.** Only the recognized HTTP-400 encrypted-content rejection family may invalidate provider artifacts. Under the canonical attempt locks, identify the exact active opaque history-row IDs and latest current-turn RunState receipt that participated in the rejected request, mark only those candidates provider-invalid, preserve their durable content/provenance, and recover the same logical turn through a temporary view that removes unusable opaque identities (and omits unusable remote-compaction blobs). If that exact candidate set invalidates nothing, fail instead of retrying an equivalent request. Never delete history, hot-swap credentials, or classify a generic 400 into this path.
- **Codex Apps authority is separate from inference.** The deployment flag only enables the feature. Execution additionally requires exactly one explicit workspace designation; null means no Apps tools and there is no active/pinned/allocator/static-credential fallback. The Apps credential is independent of inference model, billing subscription, quota, cooldown, leases, pins, capacity, and rotation. Only its current human owner with `connections:write` (or admin-equivalent scope) may designate it; any managed human with that scope may clear it. Recheck the exact designation, active connection, owner membership, and owner scope immediately before every Apps request. Reconnect never transfers ownership, and disconnect clears the designation atomically. See `docs/mcp-surfaces.md`.
- **All-exhausted Codex capacity is a durable same-turn wait, not queue or user-message recovery.** When no allocator-enabled subscription is available for an admitted Codex turn, the worker atomically closes only the exact attempt as `waiting_capacity`, preserves that nonterminal turn and the session's active-turn pointer, and persists one session waiter (with an optional active-goal version fence). The workflow waits on its authoritative reset timer or a revisioned capacity signal, reconstructs the wait after restart/`continueAsNew`, then moves that exact turn to `recovering` after row-locked allocator re-evaluation and claims it with a new attempt. Pause leaves the waiter intact for Resume to reconstruct; Steer, cancellation, and other semantic fence changes supersede it cleanly. It never creates a queue row or synthetic input, polls with model turns, duplicates inference, independently settles/requeues the blocked turn, or consumes a reset/boost entitlement. See [`docs/codex-subscription-rotation.md`](docs/codex-subscription-rotation.md).
- **Sandbox warming is bounded and tracked.** A provider instance id must be persisted on the warming lease immediately after create returns, before readiness/setup. A turn waiting on another worker's warming lease is bounded by `OPENGENI_SANDBOX_WARMING_TIMEOUT_MS` (default 600000) and fails clearly on backend capacity/create timeout instead of heartbeating forever. Rig verification reuses this canonical lease lifecycle, accepts only a clean spawner, and is gated by `OPENGENI_RIG_VERIFICATION_LEASE_OWNERSHIP_ENABLED` (default off); never restore the legacy unleased verifier. Every failed or expired warming invalidation advances the lease epoch before exposing cold/draining, permanently fencing late non-abortable provider-create callbacks from a successor acquisition. The Modal orphan sweep must immediately re-read durable attribution before terminate and fail closed when that read is inconclusive.
- **Modal checkpoints and finite deadlines are one maintenance-cutover protocol.** Migration 0138 may run only with every `opengeni_app` API/control/turn session stopped; after it commits, never start an older image. Every returned native snapshot is registered immediately as an immutable provider-bound artifact, publication rotates only exact current/previous lease references, and bounded global GC owns every unreferenced candidate/current/previous artifact even after parent deletion. Restore must consume the current receipt and compare its provider binding against the exact authenticated client embedded in the created session before hydration; a separately resolved ambient Modal client is not authority. Modal native restore never uses tar/inode/tree equivalence. Provider deadlines are stamped at create, new work is fenced once rotation is requested, and each global rotation/claim/recovery pass remains batch-bounded.
- **Every persistable `/workspace` writer uses one durable turn/direct/process authority.** Before a provider operation that may change the durable workspace, one transaction binds the exact session group, warm lease epoch, provider and pinned route to either the canonical turn-attempt holder, an API request UUID with holder `direct:<request UUID>`, or an exact retained-process UUID with holder `process:<process UUID>`, then increments `workspace_generation` and inserts its admission row. A yielded process promotes its parent admission and process holder atomically and keeps both live until exact exit/loss proof; direct and process holders never inherit the turn-quiescence fallback and block capture themselves. Ordinary turn finalization drains every registered yielded shell before capture even when no Pause/Steer receipt is required. A bounded global reconciliation may inspect direct owners or closed exact attempts after finalizer/worker death, but owner state, age, timeout, and claim expiry never prove exit: only exact provider exit/loss proof is checkpointed before the same full-identity-fenced settlement. Unknown/running/mismatched observations preserve all blockers; reconciliation never terminates a provider instance or snapshots a workspace. Definitive provider loss atomically marks only active processes on the exact lost lease epoch/provider as lost, rejects every matching open admission, closes matching PTYs, removes only their process holders, and then advances the lease epoch; unrelated or terminal rows remain untouched. The exact provider promise is physically settled whether it resolves or rejects; resolved output must separately pass the matching authority/lease/provider/route fences. Capture publishes complete only when the closed write set has no blocker and `archive_generation === workspace_generation`. Never replay an admitted operation whose provider outcome may be ambiguous.
  Admission, ordinary settlement, and yielded-process promotion share one canonical lock prefix—workspace control, workspace, session, turn/attempt or process, then admission, then lease—so parallel completion and promotion cannot deadlock and strand the checkpoint gate. Once the provider promise is terminal, retry only that exact idempotent settlement transaction on PostgreSQL deadlock/serialization failure; never replay the provider operation.
- **Worker deaths recover the same logical turn, never by manufacturing queue work.** A graceful shutdown or ungraceful worker loss checkpoints the durable conversation truth and moves the exact turn to `recovering`; the workflow claims that same turn with a new attempt UUID and generation. It does not create a prompt, resume notice, or machine-generated queue row. A dying activity never performs a competing terminal settlement, and late callbacks remain visible as rejected evidence without becoming current truth. Do not add automatic Temporal retries around the side-effectful agent activity.
- **Resource-based turn-worker memory targets remain enforced after admission.** The resource tuner prevents new activity admission when its target is already exhausted, but long-running turns can grow after they were admitted. A resource-based turn worker therefore samples whole-host `MemAvailable` plus the most pressured finite process cgroup or ancestor continuously. A sustained target breach requests the same graceful worker drain/checkpoint path used by a rollout; it never kills an activity directly, adds a turn-duration limit, discards a durable checkpoint, or replays an outcome-unknown provider operation. Fixed-concurrency and control workers do not run this guard.
- **Every turn attempt is fenced; lifecycle settlement is atomic.** Before model/tool work, a claimed turn registers a first-class UUID attempt plus its execution generation and exact Temporal dispatch. The canonical event-write order is `workspace_inference_controls FOR SHARE` when control-aware → the actual `workspaces` row `FOR KEY SHARE` → UUID-ordered sessions `FOR UPDATE` → UUID-ordered exact turns `FOR UPDATE` → UUID-ordered exact attempts `FOR UPDATE`. Generic audit/title appends skip the control row but use the same workspace-key-share prefix, so unrelated sessions in one workspace remain concurrent. Events, conversation history, run state, context replacement, input-token signals, queue/control state, system-update bundles, turn state, session pointer, and sequence commit must all reject a replaced attempt. A rejected callback is retained as `turn.event.rejected_late` evidence. A normal Send appends a prompt but never mutates an unsettled Pause/Steer fence. Never restore append-then-CAS or a dying activity's independent cancellation write.
- **Terminal session cancellation is one atomic subtree fence.** Under the workspace-control lock, Cancel marks the selected session and every existing descendant terminal, drains every queued/non-running turn and pending machine input, and interrupts live attempts without treating Temporal cancellation as physical quiescence. Send, Steer, Resume, and child creation must serialize before that commit or reject the cancelled ancestor afterward. The same transaction registers a durable wake for every affected workflow—including approval and capacity waits with no live attempt—and, when the selected root is a child, enqueues exactly one typed cancelled-child result for its surviving parent with the causal delegation snapshot. Terminal state therefore cannot leave either a cancelled Temporal run or its manager parked indefinitely. Active attempts retain exact ownership only until interruption settlement records `turn.cancelled`; their durable quiescence receipt remains authoritative.
- **Realtime is a coexisting conversational transport for the same ordinary session.** One authenticated browser owner/connection remains exclusive, but realtime never fences human composer/queue/Send/Steer or ordinary/recovery/maintenance claims. A valid provider delegation uses the exact canonical prompt `Steer` transaction with a service initiator and immutable realtime provenance. Accepted human Send/Steer mirrors once as typed silent `session.context.append`; same-call progress/result uses commentary/speakable `delegation.context.append`, while pre-existing/direct/prior-call work uses session-wide appends. Only complete provider `turn.done` rows are transcript truth. Every delegation carries the bounded finalized dialogue delta since its prior fence. End first seals and durably drains parsed provider events, then submits only the remaining finalized tail after the latest fence through canonical `Steer`; its projection row is audit/idempotency provenance, never hidden worker context, and an empty tail creates no turn. A later voice call receives bounded durable session history plus prior finalized voice turns as inert role-labeled continuity with an explicit silence instruction. WebRTC negotiation and every live delivery/ACK must prove the exact active authenticated browser owner, session, connection, and epoch before provider data moves; owner proof never crosses the broker boundary.
- **Every accepted turn freezes its initiating principal.** Human/API turns capture the authenticated subject that accepted that turn; scheduled, compaction, goal-continuation, and service-only coalesced internal work use explicit service principals. An Agent Steer remains the causal initiator when ordinary machine notices coalesce into its inference, so incidental batch timing cannot erase its inherited subject. A session creator is a separate frozen fact used only for creation attribution and idempotent first-turn repair. Queue edit/reorder never changes authority; Steer creates new authority. Agent-spawned work inherits through the worker-signed calling-turn reference and records bounded provenance. Recovery, approval, and retries preserve the same turn. Never infer authority from the session creator, sandbox token, current worker, or current queue head.
- **Workspace governance is frozen at the accepted logical-turn boundary.** After claim, every exact attempt gets immutable workspace instruction-policy and preference-descriptor snapshots reconstructed from lifecycle events as of the turn's immutable `created_at`; recovery reuses that accepted truth, while a new continuation or compaction resolves a new snapshot. A session's normalized policy role is separate from membership roles and memory selectors. Service-initiated continuations and compactions may carry the causal human solely for personal preference authority; pure service work has none, and the worker identity never substitutes. Runtime composition is deterministic, uses descriptors by default, and never promotes Documents, RAG evidence, or memory into policy authority. Full preference content remains an explicit on-demand retrieval. When no structured governance exists, preserve the exact legacy prompt path.
- **Connection ownership and executable personal authority are separate from turn initiation.** MCP and first-party social capability setup defaults to a workspace-owned connection; personal ownership requires the explicit **Connect only for me** choice. A personal connection becomes executable only through the exact immutable delegation snapshot frozen on the causal turn or scheduled task. Direct Send/Steer snapshot the authenticated subject's selected active rows; children copy the spawning `parent_turn_id`; goal continuations copy the latest finished causal turn; accepted schedule occurrences copy the task snapshot; ordinary internal updates coalesce only when their snapshots match. Recovery and approval retain the same turn snapshot. At execution, revalidate exact workspace membership plus connection id/provider/kind/owner/status; if unavailable, omit only that MCP and emit the visible personal-authority warning instead of borrowing another subject's row or aborting unrelated work. Public queue/turn/task projections expose only `{serverId, providerDomain}`, never connection UUIDs or owner subject ids.
- **Delegated service provenance never replaces authorization.** A trusted embedding host may sign a service-only causal initiator separately from the delegated grant subject. The grant subject and permissions remain the access boundary; the service assertion is immutable provenance only, cannot impersonate a human, and cannot coexist with exact worker-signed agent-attempt claims.
- **Goal mutations and their timeline facts are one session-sequenced commit.** Agent/API set, update, complete, pause, resume, and clear use the canonical event-write prefix—`workspace_inference_controls FOR SHARE` when control-aware, then the actual `workspaces` row `FOR KEY SHARE`, then the session `FOR UPDATE`—before mutating the goal and appending its event in that transaction. Agent `goal_update` additionally requires one target-scoped operation receipt that atomically stores its exact result and remains replayable across replacement attempts without overwriting a newer revision. Never mutate a goal and append/publish its event in separate commits, and never take an unnecessary workspace `FOR UPDATE` solely around a goal event: both patterns can recreate the active-turn/goal-tool self-lock.
- **Temporal cancellation is not physical quiescence.** Receipt-gated v2 workflow histories first close and fence the exact attempt in Postgres, then request nonblocking Temporal cancellation. The exact `runAgentTurn` activity owns the hard sandbox/tool fence, including draining sandbox/tool operations plus attempt-owned Git, Toolspace, and generic run-credential renewal/materialization writes, and normally writes `quiesced_at` immediately after they drain; that receipt, its queue event/session revision, and the exact workflow wake commit atomically. If all three direct receipt transactions fail, the same activity retries delivery of one immutable account/workspace/session/attempt/workflow-run/activity proof through `signalWithStart` (bounded delivery backoff, no DB re-evaluation). The workflow must persist every accepted proof before peeking, closing, or continuing as new through its DB-only control activity with unbounded Temporal retry. If the activity process disappears after logical interruption, `cancellation-wait` may recover the same receipt only after Temporal proves the exact persisted workflow-run/activity identity is absent or its server-owned heartbeat lease expired **and** the complete durable writer set is closed: the attempt is closed, its interruption is settled, and every turn admission, retained process, and retained-process child admission is physically settled. The heartbeat lease proves only that the activity owner vanished; it never substitutes for provider-operation exit/loss proof or writer settlement. Arbitrary age, workflow closure, holder expiry, or a merely requested cancellation remains insufficient. The existing Postgres receipt transaction remains the only authority that can set `quiesced_at` or open admission. NATS publication is live fanout only and neither creates nor substitutes for the receipt. Attempt-qualified credential-generation deletion plus provider/batcher/lease/cache/recording cleanup after the fence is detachable and cannot erase successor state. Until the receipt exists, every claimer stays blocked even if the Temporal activity completed or failed; the workflow may close after a bounded `cancellation-wait` and is restarted by the proof signal or wake outbox without a quiescence scanner, polling loop, synthetic prompt, effect replay, or duplicate visible work. Queue stopping telemetry is scoped to the latest attempt and may be true with an empty visible queue. Keep heartbeat cancellation delivery throttled to five seconds. Histories without the `session-attempt-quiescence-v2` patch retain the v1 WAIT/fallback command order only for deterministic replay; new histories must never take that path, and it may be removed only after those runs drain.
- **Agent Steer wake delivery is admission-aware.** Temporal accepting `sessionControl` is transport evidence, not proof that a closing or continuing workflow observed Postgres. While effective control is active and an `agent_steer_instruction` remains pending, signal delivery must not advance that session's wake-outbox acknowledgement; the bounded dispatcher keeps retrying the same coalesced revision until the attempt-fenced claim adopts the newest Steer exactly once. Duplicate signals remain wake hints and cannot duplicate inference. A real Pause is a truthful admission blocker and may acknowledge the old revision; Resume must commit a fresh wake revision for the still-pending direction.
- **Historical interruptions never become new control signals.** Wake repair emits `sessionControl` only for an undelivered control revision, an actionable interruption, or a settled interruption whose exact attempt still lacks physical quiescence. A fully quiesced historical Pause/Steer row is audit evidence only; it must never upgrade a later ordinary queue wake or cancel an unrelated live attempt.

The agent turn implementation and Temporal activity identifier are both
`runAgentTurn`; session control uses the `sessionControl` signal. The production
cutover drains and terminates every old session workflow before the new worker
starts, so no removed activity/signal identifier or replay adapter belongs in
the new runtime.

## Sandbox Notes

Sandbox execution is pluggable. `OPENGENI_SANDBOX_BACKEND` selects one of the backends defined by the `SandboxBackend` enum in `packages/contracts/src/index.ts` (the canonical list): `docker`, `modal`, `local`, `none`, `daytona`, `runloop`, `e2b`, `blaxel`, `cloudflare`, `vercel`, and `selfhosted`. `docker` is the default and the usual local-dev choice; `modal` and the other cloud backends are provisioned, swappable boxes. When you change the set of backends, update the enum first and treat it as the source of truth — this file and the README follow it.

The Docker sandbox image includes Terraform, Checkov, Azure CLI, GitHub CLI, git, jq, curl, and base shell utilities. Managed sandboxes also provision git-provider CLI auth wrappers for `gh`, `glab`, and `az`; direct provider-token bindings read their current token files at invocation time and pass through cleanly when a token file is absent. A host-owned HTTPS smart-Git broker binding is deliberately Git-only: its bearer is never exported to a provider CLI, and the wrapper fails with guidance to use the configured provider MCP tools. The seven deployment-default Terraform/checkov skills live under `packages/runtime/src/bundled_hashicorp_terraform_skills` and are mounted into the sandbox under `.agents/`; provider-specific guidance such as Azure Verified Modules is maintained separately as an immutable opt-in entry under `packages/runtime/src/bundled_skill_library` and is not part of the default mount.

### Bring-your-own-compute — the Connected Machine (`selfhosted`)

A **Connected Machine** (the `selfhosted` backend) is a user's own always-on machine — a **first-class, co-equal PRIMARY compute target**, not merely a swappable sandbox. When a turn's *effective* backend is a machine, the agent runs on it **directly**; there is no provisioned box behind it. Use "Connected Machine" in product-facing prose and reserve "selfhosted" for the enum value / internal plumbing. Key invariants — do not break them:

- **One host agent may serve many independent control planes.** A connection is identified by normalized deployment API origin + workspace id, keeps its own credentials/NATS/relay/epoch/reconnect lifecycle, and namespaces operation identity inside the shared host engine. Adding, refreshing, removing, or losing one connection must not replace, detach, cancel, or expose another; host capacity, containment, spool, and the native platform remain process-wide because they describe the one physical machine.
- **Machine-primary, not a phantom box.** A machine-targeted turn establishes the `SelfhostedSession` **directly** (`establishSelfhostedTurnSession` in `apps/worker/src/activities/agent-turn.ts`, the `machinePrimary` branch) and does **not** acquire or mutate the managed-home lease. The active-sandbox pointer supplies the machine route's epoch fence; the separate cloud lease owns only managed-box recovery, snapshots, billing, and reaping. Therefore a degraded cloud archive cannot block a healthy explicitly selected machine, and no Modal/cloud box is created, leased, or billed for that turn.
- **No platform credential or setup crosses to the machine.** A `selfhosted`-effective turn skips platform git and Toolspace minting (`sandboxEnvironmentForRun({ skipGitHubToken, skipToolspace })`), runtime runs no platform setup hooks there, and selfhosted `exec` puts `env: {}` on the wire. The machine owns its git auth, environment, and any manually provisioned API credentials. Machine unavailability must surface through the sandbox tool result; it must never fail turn admission before the model runs.
- **Repos are never cloned onto a machine.** `repositoryUsesSandboxClone` (`packages/runtime/src/index.ts`) returns `false` for a `selfhosted` effective backend (the clone-guard) — the machine already owns its filesystem, so a platform `git clone` must never land on the user's real disk.
- **Per-session working directory, not a fixed `/workspace`.** A machine runs under `sessions.working_dir` (migration 0027); `toMachinePath` (`packages/runtime/src/sandbox/selfhosted/session.ts`) re-anchors the virtual `/workspace` frame onto the chosen host path (default = the agent's launch `workspace_root`). The "`/workspace` for every run" assumption holds only for provisioned boxes.
- **Targeting a machine at create time.** `CreateSessionRequest.targetSandboxId` (+ optional `workingDir`) selects the machine for a new session; the active-sandbox pointer is seeded at creation so the **first** turn routes there (race-free). `workingDir` without `targetSandboxId` is a **422**, and an invalid/unowned/offline target **422s** rather than silently falling back to the default box (`packages/core/src/domain/sessions.ts`).
- **Never cold-create or kill a user's machine.** An offline self-hosted agent is *not* a `NotFound`; the lease never provisions a rival box, and the reaper drains a self-hosted box to cold but never provider-stops it. The capability descriptor is `persistable: false` (no disk snapshot) and the box is never idle-reaped.
- **Control surface is NATS, not a provider API.** Exec/fs/git run over a `ControlRpc` request/reply seam addressed by `agent.<ws>.<id>.rpc`, encoded via `@opengeni/agent-proto` (the protobuf wire IDL codegen'd to both Rust and TS so the control plane and agent never drift). `negotiateCapabilities` surfaces online/offline/reconnecting/consent_required/display_unavailable states.
- **Control liveness is isolated from accepted host work.** The Rust supervisor answers `ping`/heartbeats outside execution. Production admission has host-headroom-derived pathology breakers, not an ordinary concurrency or wait limit; Linux cgroup leaves fate-isolate supervisor/operations with accounting but no default parent throttle or operation memory cap, and the supervisor child must carry systemd-oomd's avoid marker before the process moves. Exec is unbounded by default and requires replayable op-stream; reconnect detaches, while explicit cancellation or a configured positive deadline kills the exact process group/Job Object. Never launch unbounded exec through legacy request/reply, move the supervisor before its child cgroup protection exists, or move host work into the heartbeat loop.
- **Gated off by default.** The whole feature is behind `OPENGENI_SANDBOX_SELFHOSTED_ENABLED` (default OFF). When off, enrollment routes 404 and the backend is inert — boot is unaffected. Related config: the `OPENGENI_SELFHOSTED_NATS_*`, `OPENGENI_SELFHOSTED_RELAY_*`, and `OPENGENI_SELFHOSTED_RELAY_TOKEN_SECRET` env vars wire the control plane, callout account, and relay tier.
- **Machine UI is opt-in.** Connected-machine React components (machines dashboard, enrollment, status pills, metrics) live on the `@opengeni/react/machines` subpath, so the `@opengeni/react` root import stays a clean sandbox-only default; the root re-exports them deprecated for back-compat (#144).
- Sandbox/enrollment/metrics tables and the session `active_sandbox_id`/`active_epoch` pointer (migration 0024) make sandboxes swappable within a session. The pointer is **establishment-safe**: a swap/seed to a target no turn can establish is rejected before the epoch-fenced CAS with a typed `code`; a persisted-unestablishable pointer is reset to the session home at turn start under the fence with a visible `session.route.reconciled` event; and a `null` pointer always resolves to the session home (the Modal group box, or the machine for a machine-home session). See `docs/architecture.md` §3.9 and `docs/connected-machines.md`.

Enabled capability packs can scope the runtime per workspace: a registered pack manifest may declare `skills` (delivered into the same `.agents/` skill index as the bundled skills) and a `sandboxImage` that replaces the global `OPENGENI_DOCKER_IMAGE`/`OPENGENI_MODAL_IMAGE_REF` for that workspace's sessions. At most one enabled pack per workspace may declare an image — no image composition. See `docs/packs.md`.

When the `azure` sandbox preparation profile is enabled and ARM/AZURE service-principal variables are allowed into the sandbox, the worker pre-authenticates normal Azure CLI inside the sandbox with `az login --service-principal` before the agent starts. There is no custom `opengeni-azure-login` helper.

Sandbox preparation is controlled by:

- `OPENGENI_SANDBOX_PREPARATION_PROFILES=none`, `azure`, `github`, or comma-separated profile names
- `OPENGENI_SANDBOX_ENV_ALLOWLIST=...` for extra explicit host env vars

Explicit `OPENGENI_GIT_*` settings can set sandbox git author/committer identity. Ambient host `GIT_AUTHOR_*` and `GIT_COMMITTER_*` variables only pass through when the `github` preparation profile or env allowlist permits them.

Do not expect model provider credentials to automatically appear in the sandbox unless explicitly allowed.

The API and sandbox file-resource object-storage boundary supports `s3-compatible`, `azure-blob`, `aws-s3`, and `gcs`. Azure Blob-backed Docker/local sandboxes use native Azure Blob manifest mounts. Modal Azure Blob, AWS S3, and GCS file resources use short-lived signed download materialization.

## Deployment Work Notes

When working on production deployment, Azure/AWS/GCP deployment, Helm, Terraform, conformance checks, preview variable-sets, observability, or cloud-provider-agnostic infrastructure, treat the source as authoritative: deployment contracts in `packages/deployment`, the Helm chart under `deploy/helm/opengeni`, Terraform roots under `deploy/terraform`, stack wrappers under `deploy/stacks`, and operator docs in `docs/deployment.md`.

Every new SQL migration must declare its reviewed production path on the first lines: `-- deployment-mode: rolling` for online-compatible expand-and-contract work, or `-- deployment-mode: maintenance` for an incompatible one-way cutover. The protected production gate hashes the ordered SQL history and rejects rewrites or unclassified additions.

Migration `0117_sandbox_recovery_generations.sql` is a one-way maintenance cutover. Stop every old API, control-worker, and turn-worker writer before activation; activation rejects a live `opengeni_app` session and rolls its transaction back cleanly. Application/image rollback to an old writer is allowed only before migration activation. After activation, no old writer may restart; move forward with the protocol-v2 application because there is no mixed-version or down-migration path.

Keep provider resource inventories, cleanup notes, cloud account identifiers, private endpoints, generated credentials, kubeconfigs, Terraform state, plans, local tfvars, service-account keys, and access keys in private operator-controlled storage outside the repository.

Use official upstream charts/operators or managed services for production platform services. OpenGeni's chart should own OpenGeni API, web, worker, migrations, and integration resources. Built-in Postgres, Temporal, NATS, and MinIO templates are disposable conformance fixtures for local, CI, and smoke verification only; do not present them as lightweight production alternatives.
